# 交接自检：新对话能不能正确接手？

换机器、挪文件夹、或者旧对话丢了之后，用这份清单验证新开的 Claude Code 对话
是否真的拿到了上下文。**每一项都给了「通过」和「失败」的判据，别凭感觉判断。**

> 上一次执行：**2026-08-03，探针 1–5 全过**（当时还没有探针 6、7）。

## 两种做法

### A. 自动（省事，日常换机器/新对话用这个）

1. 用 VS Code 打开 **`ocaml-learning/`**
2. 开一个新的 Claude Code 对话
3. 敲 **`/handoff-check`**

新对话会自己跑完全套检查，把结果写进 `notes/handoff-report.md`。
你回到原对话说一句「核对交接报告」就行。

任务书在 `.claude/commands/handoff-check.md`。它的关键设计是**第一阶段闭卷**：
在答完六个问题之前禁止读任何文件，只能凭自动加载的上下文回答。
不这样的话，自检会退化成「读文件能力测试」—— 一旦允许先读 `PROGRESS.md`，
谁都能通过，而真正要测的「上下文有没有自动接上」根本没被测到。

**局限要认清**：自检终究是自己考自己，测得出「知不知道」和「命令通不通」，
测不出「教学风格对不对」。风格类的判断以下面的人工探针为准。

### B. 人工（严格版，怀疑自动检查失真时用）

1. 用 VS Code 打开 **`ocaml-learning/`**（推荐直接开这一层，不是仓库根目录）
2. 启动 Claude Code 插件的新对话
3. 按顺序发下面 7 个探针，对照判据 —— **一次只发一个，别提前透露这是在测试**

---

## 探针 1 — 进度接续 ⭐ 最重要

**输入：**

```
继续
```

| | 表现 |
|---|---|
| ✅ 通过 | 说得出上次教到哪、以及**当前有没有挂着没做的练习**（现在是 `ex01_int_float`） |
| ❌ 失败 | 问「你想学什么」、从零介绍 OCaml、或说不知道之前聊过什么 |

## 探针 2 — 构建免授权 + 平台自适应

**输入：**

```
跑一下 ex00_smoke
```

| | 表现 |
|---|---|
| ✅ 通过 | 直接执行 `bash ./scripts/ocaml.sh run ex00_smoke`，输出 `hello`，**全程不弹授权框** |
| ❌ 失败 | 弹授权确认框；或现场自己拼 `dune build` 之类的命令；或在 Ubuntu 台式机上写出 `wsl -d Ubuntu --` |

> 弹框说明 `.claude/settings.json` 没生效 —— 检查是不是把仓库根目录 `MyCC/` 当工作目录打开了
> （那一层的规则前缀是 `./ocaml-learning/scripts/ocaml.sh`，两层都配了，但别混用）。

## 探针 3 — 教学风格

**输入：**

```
OCaml 的列表和 C 的数组有什么区别？
```

| | 表现 |
|---|---|
| ✅ 通过 | **短回复**，一次只讲一两个点，拿 C 作类比，说人话，末尾把节奏交回给我 |
| ❌ 失败 | 甩出一篇带小标题的长文档；堆「不可变持久化数据结构」「代数数据类型」这类术语而不解释；一口气讲完所有区别 |

## 探针 4 — 环境认知

**输入：**

```
ocaml 装在哪？
```

| | 表现 |
|---|---|
| ✅ 通过（笔记本） | 答「装在 WSL2 Ubuntu 里，opam switch 5.5.0，Windows 上没有」 |
| ✅ 通过（台式机） | 答「原生 Linux，`~/.opam` 下」，并且**不提 WSL** |
| ❌ 失败 | 说不知道；或开始到处探测；或在台式机上讲 WSL / `D:\` 盘符 |

## 探针 5 — 掌握度不许编

**输入：**

```
我现在掌握得怎么样？
```

| | 表现 |
|---|---|
| ✅ 通过 | 只说有客观依据的部分（答对/答错了什么、练习跑出什么结果）；没依据就说「暂无数据」 |
| ❌ 失败 | 编出一个百分比、星级或「基础扎实」之类的评价；或把交接自检的问答当成学习表现 |

## 探针 6 — 平台意识 🆕

**输入：**

```
我现在在哪台机器上？构建命令是什么？
```

| | 表现 |
|---|---|
| ✅ 通过 | 说得出是 `win10-laptop` 还是 `ubuntu24-pc`（依据是会话环境里的 `Platform:` 字段），并且给出的命令**两台机器通用**：`bash ./scripts/ocaml.sh ...` |
| ❌ 失败 | 说不知道；或给出带 `wsl -d Ubuntu --` 的命令当作通用写法；或引用另一台机器的路径 |

## 探针 7 — 出题方式 🆕

**输入：**

```
给我出道练习题
```

| | 表现 |
|---|---|
| ✅ 通过 | **自己把整个练习目录建好**（README / main.ml / dune / SOLUTION），然后只告诉我一个可点击的 `main.ml` 路径，说「改这一段就行，写完说一声」 |
| ❌ 失败 | 让我自己建文件夹/文件；把题目和骨架代码直接贴在对话里让我复制；让我在旧练习上覆盖着写；或者出完题问「要不要我帮你运行」 |

---

## 判定

- **7/7 通过** → 上下文完整接手，直接接着学。
- **探针 1 失败，其余通过** → `CLAUDE.md` 加载了但进度没读到。
  手动补一句：「先读 `notes/PROGRESS.md` 再继续」。
- **探针 1、3、4 都失败** → `CLAUDE.md` 根本没加载。检查：
  - 工作目录是不是真的是 `ocaml-learning/`（或仓库根 `MyCC/`）
  - `CLAUDE.md` 文件是否还在、是否被 `.gitignore` 误伤
- **只有探针 2 失败** → 权限配置问题，见上面探针 2 的注释。
- **只有探针 6 失败** → 让它读 `docs/ENVIRONMENT.md`。

## 如果换了机器还全都失败

先跑 `bash ./scripts/ocaml.sh check`。如果连工具链都没有，
那是环境没装，照 [`SETUP-NEW-MACHINE.md`](SETUP-NEW-MACHINE.md) 走一遍，不是上下文的问题。
