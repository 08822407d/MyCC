**规则：任何跟平台有关的东西（路径、磁盘、扩展安装位置、绕过脚本的命令），
先看 `Platform:` 字段确认在哪台，再动手。不确定就跑 `bash ./scripts/ocaml.sh platform`。**

平台细节分开放：

- `docs/env/COMMON.md` — 两台都成立（版本口径、踩过的坑、原则）

**别把单机事实当通用事实说出口。** 典型错误：在台式机上讲 `wsl -d Ubuntu --`，
或者引用 `D:\` 盘符 —— 那台机器上根本没有这些东西。

## 1. 构建命令：两台机器完全一样

```bash
bash ./scripts/ocaml.sh <子命令> [参数...]
```

`scripts/ocaml.sh` 自己识别平台：在 Windows 的 Git Bash 里会 `exec` 进 WSL 再跑。
**所以不要再手写 `wsl -d Ubuntu --` 前缀了**，写了反而只能在一台机器上用。

从仓库根目录 `MyCC/` 打开时，路径带前缀：`bash ./ocaml-learning/scripts/ocaml.sh ...`
（推荐直接把 `ocaml-learning/` 作为工作目录打开）。两种情况的免授权规则都已配好。

| 子命令 | 用途 |
|---|---|
| `platform` | 一行输出当前平台 |
| `check` | 环境自检：平台 + 工具路径 + 版本 |
| `list` | 列出所有练习 |
| `new <名字>` | 新建练习骨架（dune + main.ml + README + SOLUTION） |
| `build [名字]` | 构建 |
| `run <名字> [参数]` | 构建并运行 ← **验证练习就用这个** |
| `test [名字]` | 跑测试 |
| `eval '<代码>'` | **教学主力**：一小段 OCaml 丢进顶层，直接回显类型和值 |
| `evalfile <文件>` | 同上，从文件读（代码里有单引号时用它，省得跟 shell 打架） |
| `fmt` / `clean` / `repl` | 格式化 / 清理 / utop（repl 需交互终端，Claude 用不上） |

`eval` 的输出长这样，教学时最有用：

```
$ bash ./scripts/ocaml.sh eval 'let add a b = a + b'
val add : int -> int -> int = <fun>
```

**一律用相对路径 `./scripts/ocaml.sh`。** 脚本自己推导项目根目录，文件夹整个挪走也不坏，
而且免授权白名单是按命令前缀匹配的，写成绝对路径一搬家就失效。

## 1.5 命令免授权（Agent 行为配置）

> 目前用的 Agent 只有 **Claude Code**。这一节记录「哪些命令不用弹框确认」的机制和现状，
> 换 Agent 或换机器时照这个恢复。

### 机制

Claude Code 读 `.claude/settings.json` 的 `permissions.allow` 数组，**按前缀通配匹配**：

- `"Bash(git status *)"` —— 匹配 `git status`、`git status --short` 等
- `"Bash(bash ./scripts/ocaml.sh *)"` —— 匹配这个脚本的所有子命令
- 工具名要写对：`Bash(...)` / `PowerShell(...)` / `Write(...)` 是不同的工具

⚠️ **`settings.json` 是严格 JSON，写注释会让整个文件失效**（连带所有规则一起失效）。
所以分类说明只能放在这里，不能放在那个文件里。

### 为什么两层各有一份

| 文件 | 何时生效 | 脚本路径前缀 |
|---|---|---|
| `ocaml-learning/.claude/settings.json` | 把 `ocaml-learning/` 作为工作目录打开（**推荐**） | `./scripts/ocaml.sh` |
| `../.claude/settings.json`（仓库根） | 把 `MyCC/` 作为工作目录打开 | `./ocaml-learning/scripts/ocaml.sh` |

**规则里的路径是相对工作目录的**，所以两层内容不能互相照抄，只能各写各的。
一律用**相对路径**——写成绝对路径的话，文件夹一搬家规则就失效。

### 已放行的三类

1. **两台机器通用**：`ocaml.sh` 的所有子命令（`bash ./scripts/ocaml.sh *`），
   以及 Linux 上的直接调用（`./scripts/ocaml.sh *`，脚本已有可执行位）
2. **只读 git**：`git status` / `log` / `diff` / `show` / `branch` / `ls-files` / `ls-remote` / `remote -v`
3. **只在 `win10-laptop` 生效**：`wsl -d Ubuntu -- bash ./scripts/ocaml.sh *` 及其 PowerShell 版
   —— 这条在台式机上永远匹配不到，无害

### 故意**不**放行的（重要）

| 没放行的 | 理由 |
|---|---|
| `git commit` / `push` / `pull` / `reset` 等**写操作** | 用户明确要求 git 一律等他开口（见第 6 节）。**弹框正是最后一道闸** |
| `Bash(wsl -d Ubuntu -- bash -lc *)` | 那是**裸 shell**，放行等于给任意命令开口子。虽然查工具版本时常用，但不值得 |
| `Bash(git *)` 这种大而全的写法 | 会把 `push` 一起放进去 |

### 已知限制

**复合命令可能仍然弹框。** 像 `cd /d/MyCC && git status --short && git log -3` 这种用 `&&`
串起来的，匹配行为不保证。要少弹框就**尽量一条命令做一件事**。

### 怎么加新规则

1. 先读现有文件（**不要整体覆盖，要合并**，否则会删掉已有规则）
2. 判断这条命令是否**只读、可重复执行、不改变仓库外的状态**——是才加
3. 两层都要考虑：这条命令在另一个工作目录下路径长什么样
4. 加完确认 JSON 仍然合法（`python -m json.tool` 或 `jq . <文件>`）

**C 习惯迁移观察清单**（发现新的就往下加）：

| C 习惯 | OCaml 里 | 后果 |
|---|---|---|
| `f(x)` 调用括号 | 应为 `f x` | 单参数时无害，**多参数 `f(a, b)` 会变成传一个二元组**，撞类型错误 |

| 想改变量 | 默认不可变，要 `ref` / `:=` / `!` | —— |
| `(5 : float)` 当强制转换用 | 那是**断言+核对**，OCaml **没有转换语法**；要转就 `float_of_int 5` 或直接写 `5.` | 编译错误（好在会报错，不会静默）。**2026-08-06 晚复习第 7 题实测他中招** |
