# 术语表

> 约定见 `CLAUDE.md` 第 3 节 —— **术语第一次出现时写成「粗体中文（English）」**。
>
> **这张表只收「已经讲过并解释清楚的」**。提到但没展开的放在最后一节，别混。

## 已讲过的

| 中文 | English | 一句话 | 出处 |
|---|---|---|---|
| **绑定** | binding | 把一个名字关联到一个值；**绑完不能改**，和「变量」不是一回事 | 知识点 1 |
| **不可变** | immutable | 值造出来之后不能被修改。OCaml 的默认状态 | 知识点 1 / 8 |
| **遮蔽** | shadowing | 用同名的新绑定挡住旧绑定。**被挡住的是名字，旧绑定原封不动还活着** | 知识点 3 |
| **作用域** | scope | 一个名字有效的代码范围。`let … in <body>` 里的 `<body>` 就是作用域 | 知识点 3 |
| **词法作用域** | lexical scoping | 一个名字指向谁，只看它**写在代码的什么位置**，与运行时怎么走无关。也叫静态作用域 | 知识点 8 |
| **一等值** | first-class value | 能像普通值一样被起名、传参、返回、装进容器。OCaml 里**函数和 `ref` 都是一等值** | 知识点 4 / 8 |
| **柯里化** | currying | **语言的设计**：`a -> b -> c` 本来就是一串单参数函数，不存在真正的多参数函数 | 知识点 4 |
| **部分应用** | partial application | **你的用法**：只喂一部分参数就停手，拿到一个新函数（如 `List.map (add 3)`） | 知识点 4 |
| **闭包** | closure | 函数连同它捕获的那些绑定。`make_counter` 返回后 `r` 仍然活着，就是闭包持有着它 | 知识点 4 / 8 |
| **脱糖** | desugaring | 前端把语法糖改写成更基本的形式，好让后面阶段少处理一种结构。如 `let x = e1 in e2` ≡ `(fun x -> e2) e1` | 知识点 4 |
| **传值调用** | call by value | 参数**先算成值**再传进函数，所以参数的副作用**恰好发生一次**（对比 C 宏的文本替换） | 知识点 4 |
| **副作用** | side effect | 除了算出值以外还对外界做了什么（打印、写文件、改 `ref`）。类型里出现 `-> unit` 基本就是它 | 知识点 4 / 6.7 |
| **顶层** | toplevel | 交互式解释器（`utop` / `ocaml`）。**`;;` 是顶层的规矩，不是语言的一部分** | 知识点 6 |
| **元组** | tuple | **逗号造元组，圆括号只是分组、不是必需的**：`1, 2, 3` 和 `(1, 2, 3)` 同一个东西。<br>⚠️ **`[1, 2, 3]` 是「一个三元组的列表」**，不是三个元素（方括号才是列表，逗号造了一个元素）。<br>⚠️ **括号只能包最外层**：`((1,2), 3)` 是 `(int*int)*int`，和 `int*int*int` **是不同类型**，不能互换。<br>对比：类型箭头 `->` 右结合，加括号不改变含义；元组的 `*` **不结合**，括号承载语义 | 知识点 6.2 / 2026-08-06 补 |
| **记录** | record | 有**命名字段**的复合类型，≈ C 的 `struct` / C# 带字段的 class | 知识点 8 |
| **类型构造器** | type constructor | 吃一个类型、产出一个类型的东西。**后缀写法**：`int list`、`string option`、`int ref` | 知识点 8 |
| **thunk** | thunk | 用 `fun () -> e` 把一段还没算的计算包起来，调用一次才算。用于**显式延迟求值** | 知识点 4 |
| **穷尽性检查** | exhaustiveness checking | 编译器验证 `match` 是否覆盖所有情况，没覆盖就 `Warning 8`，**并举出一个没匹配到的例子** | 2026-08-06（公开课嵌套 match 的例子） |
| **通配符模式** | wildcard pattern | `_`：匹配任何值、**不绑定任何名字**。⚠️ **它是模式不是关键字**，和 C# 的 `default` 不同——可以出现在模式的**任意位置、任意多次**（`_, "164", _`）。<br>⚠️ **模式出现的地方远不止 `match`**：函数参数、`let` 左边、`fun` 参数**本质上都是模式**（所以 `let (a, b) = pair` 能解构）。<br>⚠️ **类型位置上的 `_` 是另一个意思**：「这个类型你自己推」，如 `(x : _ list)` | 2026-08-06 |

| **模式变量** | pattern variable | 模式里的**小写名字**。它不是在匹配什么，而是**当场新建一个绑定**接住匹配到的那部分数据。<br>`\| Circle r -> …` 里的 `r` 是**你自己起的**，改成 `whatever` 结果完全一样。<br>⚠️ **OCaml 标识符不能用中文**：`Invalid character U+534A in identifier` | 知识点 9.3 |
| **构造器** | constructor | 造出某个类型的值的名字，**首字母必须大写**（语法规定）。带 `of` 的是「模子」，要填空才成为值。⚠️ **构造器不是函数**，不能部分应用 | 知识点 9.2 |
| **基准情形** | base case | 递归里**不再递归、直接给答案**的那一支。递归的出口 | 知识点 10.4 |
| **递归情形** | recursive case | 把问题**变小一点**再交给自己。⚠️ 光有出口不够，**每次必须朝出口靠近**，否则照样溢出 | 知识点 10.4 |
| **尾调用** | tail call | 函数体里「最后一件事」就是调用另一个函数，**结果直接当自己的返回值，中间不再加工** | 知识点 10.6 |
| **尾递归** | tail recursion | 尾调用的对象是自己。OCaml **复用栈帧**（`call` 退化成 `jmp`），一亿层也不溢出。<br>⚠️ **判据是「还有没有事」不是「事有多大」**：`1 + f x` 加的只是常数，照样炸（**已实测**）。<br>⚠️ **.NET 的 JIT 不保证尾调用优化**，同样写法在 C# 里会 `StackOverflowException` | 知识点 10.6 |
| **求值** | evaluate | 把表达式算出结果，**发生在运行时**。就是 C 里的「算出来」，**没有别的意思**。<br>唯一区别：OCaml 里能求值成值的东西更多（函数、`if`、`match` 都是表达式） | 知识点 0 |
| **值** | value | 已经算完、没法再往下算的东西。⚠️ **OCaml 的「值」比 C 宽**：函数本身就是值 | 知识点 0 / 4 |
| **词法作用域** | lexical / static scoping | 一个名字指向谁，由它**写在源文件的哪个位置**决定，**编译期就定死**。<br>OCaml / C / C# 都是这一套。**判据：看文本包不包，不看谁调用** | 知识点 10.7 |
| **动态作用域** | dynamic scoping | 由**调用发生时的环境**决定。**bash 就是这样**（已实测演示）。<br>⚠️ 2026-08-07 用户的错误推理正好是这一套，**给它起名字之后他立刻理解了** | 知识点 10.7 |
| **相互递归** | mutual recursion | `let rec f = … and g = …`，两个绑定**互相可见**。<br>⚠️ **这里的 `and` 不是「并且」**，是「扩大作用域覆盖这几条」 | 知识点 10.7 |
| **闭包** | closure | 一个函数**连同它看得见的外层变量**打包成的整体。OCaml 里是堆上的对象，<br>所以**能活得比创建它的作用域久**（函数可以当返回值）。<br>⚠️ 对比：C 的 GNU 嵌套函数外层一 `return` 就悬垂 —— 详见 `side-topics/c-nested-functions-trampoline.md` | 知识点 10.7 |

## 命名对照（容易混的）

| 看着像，其实不是 | 说明 |
|---|---|
| `!r` 不是「逻辑非」 | 逻辑非是 `not`；`!` 是**读 `ref` 的内容**，等价于 `r.contents` |
| `==` 不是「等于」 | `==` 是**物理相等**（同一块内存）；结构相等是 `=`。`"a" == "a"` 是 `false` |
| `ref` 不是 C# 的 `ref` | C# 的 `ref` 是**别名**、不是一等值；OCaml 的 `ref` 是**堆上的单字段可变记录**，≈ C# 的 `class Box<T> { public T Value; }` |
| `unit` 不是 `void` | `unit` 是**真类型**，有唯一真值 `()`，能进容器、能当参数 |
| 「函数签名」 | 在 OCaml 里指 `.mli` 的模块接口，**不要**用它指函数的类型 |
| `%b` 不是二进制 | **OCaml 的 `%b` 是 `bool`**，`Printf.sprintf "%b" 255` 是类型错误。<br>而且**OCaml 没有二进制占位符**。`%x` / `%X` / `%o`（十六进制/大写/八进制）和 C 一致，<br>`%08x` / `%5d` / `%-5d`（补零/右对齐/左对齐）也和 C 一致。**2026-08-07 用户按 C 直觉猜时发现** |
| 注释不像 C 的 `/* */` | **OCaml 注释可以嵌套**，所以注释里出现 `(*` 会开一个新注释。<br>把 C 代码片段抄进注释时极易中招：`(* int (*f[10])(void) *)` **编译不过**（`Comment not terminated`）。<br>解法：星号和左括号之间加空格 —— `int ( *f[10] )(void)`。**2026-08-06 我自己连踩两次** |
