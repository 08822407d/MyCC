## 12.1 切入题：`[1; 2; 3]` 和 `1 :: [2; 3]` 什么关系

**答案：完全相同**（实测 `[1; 2; 3] = 1 :: [2; 3]` → `true`）。

用户当时的疑问很准：**"给内容追加列表，是平铺成一层，还是把整个列表当成一个元素？"**
—— 答案是**平铺**，而且另一种读法**在编译期就被类型堵死了**：

```
$ eval 'List.cons'          - : 'a -> 'a list -> 'a list = <fun>
                                  ↑元素     ↑表        ↑还是那个表
```

三处 `'a` 是**同一个类型**。要嵌套就得让 `::` 左边是 `int list`。决定性证据：

```
[1; [2; 3]]
Error: This expression should not be a list literal, the expected type is int
```

**列表所有元素必须同类型**（编译期检查），所以"一个 int 和一个 list 并排"这个形状不存在。
真要嵌套得两边都是表：`[[1]; [2; 3]]` → `int list list` ✅

## 12.2 `::` 不是"追加"，是"在头上接一个"

`[1; 2; 3]` 只是语法糖：

```
1 :: 2 :: 3 :: []   →   [1; 2; 3]
```

`[]` 是空表，链条的终点。

## 12.3 ⭐ 对着 C 看：**它是单向链表，不是数组**

```c
struct node { int head; struct node *tail; };
```

`::` = malloc 一个新节点，`head` 放新元素，`tail` 指向原来那张表；`[]` = `NULL`。

**这直接决定该怎么写代码：**

| 操作 | 代价 |
|---|---|
| 取头、在**头部**加（`::`） | **O(1)** |
| 取第 n 个、求长度、**尾部**加 | **O(n)** |

> **OCaml 代码里满地都是「`x :: acc` 攒着，最后 `List.rev` 翻过来」——因为只有头部便宜。**
> 这正好配 10.6 的尾递归累加器套路。

**他在 C 里对单向链表的所有直觉，这里全能搬。**

## 12.4 `::` 不复制（不可变性买到的实惠）

```
let t = [2; 3] in let u = 1 :: t in (List.tl u == t)   →   true
```

`==` 是物理相等（知识点 5）。**新表的尾巴就是原来那张表本身**，只新建了一个节点。

**在 C 里你不敢这么共享**——别人可能改它。OCaml 里列表不可变，共享**永远安全**。
**省内存、省拷贝，不是哲学。**

## 12.5 尾部追加：`@`，而且要避开它

```
( @ )          →  'a list -> 'a list -> 'a list      (接两张表，不是一个元素)
[2; 3] @ [4]   →  [2; 3; 4]
```

**代价是 O(n)，而且是左边那条的 n。** 实测能看见发生了什么：

```
let a = [1; 2] in let b = [3] in let c = a @ b in
(List.tl (List.tl c) == b,  c == a)   →   (true, false)
```

**右边整条被共享（true），左边被完整复制（false）。**

**为什么非复制不可**：要在尾部接就得改最后一个节点的 `tail`，但 ① 节点不可变
② 别人可能正共享着这张表。所以只能重造左半段。
（C 里单向链表尾部加**也是 O(n)**，除非另存 tail 指针；OCaml 存不了，那需要可变。）

> ⚠️ **循环里用 n 次 `@` 是 O(n²)，这是 OCaml 最常见的性能陷阱之一。**
> 标准做法：`::` 往头上塞，最后 `List.rev` 一次 → 总共 O(n)。

## 12.6 ⭐⭐ 列表就是一个 ADT（**这一条解开了用户最大的困惑**）

用户问：「match 列表时的逻辑是不是和其他类型不太一样？」
**答案：完全一样，因为 `[]` 和 `::` 就是列表这个 ADT 的两个构造器。**

手写一个，和内置的逐行对应：

```ocaml
type mylist = Nil | Cons of int * mylist        (* 手写 *)

let rec mylength l =              let rec length2 l =
  match l with                      match l with
  | Nil -> 0                        | [] -> 0
  | Cons (_, rest) -> 1 + …         | _ :: rest -> 1 + …
```

| | `shape` | 手写列表 | 内置列表 |
|---|---|---|---|
| 定义 | `Circle of float \| Rect of …` | `Nil \| Cons of int * mylist` | `[] \| (::) of …` |
| **造** | `Circle 2.0` | `Cons (10, Nil)` | `10 :: []` |
| **拆** | `\| Circle r ->` | `\| Cons (x, rest) ->` | `\| x :: rest ->` |

**内置定义真的就是这个形状**，照抄能编译：

```
type mylist2 = [] | (::) of int * mylist2                    ✅
let l = 1 :: 2 :: []   →   val l : mylist2 = (::) (1, (::) (2, []))
```

**注意最后那行输出**：我定义了 `[]` 和 `(::)`，写 `1 :: 2 :: []`，编译器**用的就是我的构造器**，
还把值印成 `(::) (1, (::) (2, []))`。

### 那为什么"感觉"不一样？三个纯表面原因

1. **构造器长得像运算符**：叫 `::` 不叫 `Cons`，而且是**中缀**的 ← **唯一真正的区别，纯粹是摆放位置**
2. **有专门的字面量语法** `[1; 2; 3]`，把真身藏起来了
3. **`[]` 看起来像"空"**，不像构造器名

### 编译器自己承认

```
let f l = match l with [] -> 0 | Cons (x, r) -> 1
Error: This variant pattern is expected to have type 'a list
       There is no constructor Cons within type list
```

**"There is no constructor `Cons` within type `list`"** —— 在编译器眼里列表就是个普通 ADT。

## 12.7 列表的 match 只有两条分支

因为只有两个构造器。写全就零警告；漏一条 Warning 8 会**点名**：

```
match lst with x :: rest -> …
Warning 8 [partial-match]: ... a case that is not matched: []
```

**和递归天生一对**（回到 10.4 的两条硬性要求）：

| 要求 | 列表怎么自动满足 |
|---|---|
| 必须有基准情形 | `[]` 那条就是 |
| **每次必须朝基准靠近** | `rest` 比 `lst` **正好短一个** |

> **第二条在整数递归里最容易写错**（`sum (n+1)` 那种死循环），
> 换成列表**不容易错**——`::` 一次只能拆一个头，方向被结构定死。

⚠️ **但「不可能错」是我原来的说法，已被实测推翻，别再那么讲。**
2026-08-08 用户做 ex03 TODO 4 时写出了：

```ocaml
let rec go acc rest =
  match rest with
  | [] -> acc
  | x :: tl -> go (acc + x) rest      (* ← 传的是 rest 不是 tl *)
```

**结构确实拆出了 `tl`，但他可以选择不用它** —— 把原表原样传回去，
`acc` 一直涨、表一直不变，**死循环**（当时把整个自测跑挂了）。

> **准确的说法**：`::` 保证你**能**拿到一个更短的表，**不保证你会用它**。
> 判据还是 10.4 那条：**每次递归必须朝基准情形靠近。**
