# 8. 不可变性与 `ref`

> 2026-08-06 讲的。**这是回到原路线后的第一个知识点**（3、4、6、7 都是被公开课问题拽出来的）。
> 设计意图之一是压 `MASTERY.md` 记的薄弱点「绑定 vs 赋值」。
>
> ⚠️ 本篇按 2026-08-06 定的**术语排版约定**写（术语卡 + 粗体括号英文），见 `CLAUDE.md` 第 3 节。

## 一、默认不可变

> **不可变（immutable）** — 值一旦造出来就不能被修改。OCaml 的**默认状态**，不是可选项。

和 C/C# 相反：那边默认可变，想要不可变得写 `const` / `readonly`。

> **绑定（binding）** — 把名字关联到值。**绑完不能改**，和「变量」不是一回事。

## 二、遮蔽 ≠ 赋值（三个实验）

> **遮蔽（shadowing）** — 用同名新绑定挡住旧绑定。**挡住的只是名字，旧绑定原封不动还活着。**

```ocaml
let x = 1 in let f () = x in let x = 2 in f ()           (* ① → 1 *)
let r = ref 1 in let f () = !r in r := 2; f ()           (* ② → 2 *)
let r = ref 1 in let f () = !r in let r = ref 2 in f ()  (* ③ → 1 *)
```

**③ 是决定性的**：用了 `ref` 结果照样是 1 —— 说明区别不在「是不是 `ref`」，在**遮蔽 vs 赋值**。

| | 干了什么 | `f ()` 看到 |
|---|---|---|
| ① `let x = 2` | 造**新绑定**，重名 | 1 |
| ② `r := 2` | 改**盒子内容**，绑定没动 | 2 |
| ③ `let r = ref 2` | 造**新盒子**，名字指过去 | 1 |

`Warning 26 [unused-var]` 会指着 ①③ 里新绑的那个名字说「没被用过」—— 白送的证据。

## 三、词法作用域：两件事，两个时间点

> **词法作用域（lexical scoping）** — 一个名字指向谁，**只看它写在代码的什么位置**，与运行时怎么走无关。也叫静态作用域。

- **求值**（算出值）→ 运行时，`f ()` 那一刻
- **名字解析**（读哪个 `x`）→ 写代码时就定死了

**用户当时把这两件事合并了**，据此推断①应该是 2。前半句「函数体被调用时才求值」完全正确，
漏的是后半句。他还猜「定义时绑定了旧值的地址」——**方向对，但那描述的正是 `ref`**。

### ⭐ 用户在这里提了一个很尖锐的反驳（值得记住）

他指出：**①根本证明不了「调用时才求值」**，因为结果 1 和「定义时就把值算好存起来」也相容。
**这个批评是对的。** 他提议「在遮蔽前修改 x 的值」来区分 —— 逻辑正确，
但**对普通 `let` 无法实施**（不可变 = 根本没有「修改」这个操作），换成盒子就恰好是实验②。

补充的第三条证法（不需要 `ref`）—— 把**副作用**放进函数体看打印顺序：

```ocaml
let x = 1
let f () = print_string "<函数体跑了>"; x
let () = print_string "<定义已完成>"
let () = ignore (f ())
(* 输出：<定义已完成><函数体跑了>  —— 定义那步没有执行函数体 *)
```

**延伸结论（接他的编译器目标）**：函数体只有纯计算 + 不可变数据时，
「定义时算好」和「调用才算」**观察不到区别** → 编译器可以自由常量折叠、内联。
一旦有副作用或可变状态，两者立刻可区分。**这是函数式语言好优化的核心原因之一。**

## 四、`ref` 是什么：单字段可变记录

> **记录（record）** — 有命名字段的复合类型，≈ C 的 `struct` / C# 带字段的 class。

```ocaml
type 'a ref = { mutable contents : 'a }
```

顶层直接印成记录字面量：`val r : int ref = {contents = 1}`。

所以三件套全是**记录字段读写的语法糖**：

| 写法 | 等价于 | 类比 C |
|---|---|---|
| `ref 1` | `{ contents = 1 }` | `malloc` 一个 int 并初始化 |
| `!r` | `r.contents` | `*p` |
| `r := 2` | `r.contents <- 2` | `*p = 2` |

证据：用普通字段访问能手写出和 `!` 类型完全相同的函数 ——
`let my_deref r = r.contents` → `'a ref -> 'a`。

⚠️ **`!` 不是逻辑非**，逻辑非是 `not`。

## 五、像指针，但不是指针（用户主动问的）

实现层面是（堆上一格），类型层面不是（是记录）。**关键是别把 C 指针的能力带过来：**

| | C `int *p` | C# `ref` | OCaml `int ref` |
|---|---|---|---|
| 指针算术 | ✅ | ❌ | ❌ |
| 可以为空 | ✅ | ❌ | ❌ |
| 类型安全 | ❌ | ✅ | ✅ |
| **是不是一等值** | ✅ | ❌ **别名 + 生命周期限制** | ✅ |

> **一等值（first-class value）** — 能像普通值一样被起名、传参、返回、装进容器。

**用户问「是不是像 C# 安全模式下的 `ref`」**：安全性那一面对，但 C# 的 `ref` 是**别名**、
**不是一等值**。更准的对应物是 `class Box<T> { public T Value; }`。

**别名分析那一行对写编译器最有意义**：C 指针能指任何地方，编译器没法证明
「这次写不会影响那次读」，大量优化做不了；OCaml 里可变位置只能显式造出来，别名范围小得多。

## 六、`ref` + 闭包

> **闭包（closure）** — 函数连同它捕获的那些绑定。

```ocaml
let make_counter () = let r = ref 0 in fun () -> (r := !r + 1; !r)
(* c = make_counter () 之后：c () → 1, 2, 3 … 两个计数器互不干扰 *)
```

`make_counter` 已经返回，`r` 却还活着 —— **闭包**持有着它。**这是「闭包 + 可变状态」的经典写法，很实用。**

> 顺带：C# 里 lambda 捕获局部变量时编译器也是生成隐藏类把变量变成字段 —— 同一个机制。

## 七、类型构造器是后缀的

> **类型构造器（type constructor）** — 吃一个类型、产出一个类型的东西。

```ocaml
int list   string option   int array   int ref   int ref list
```

`int ref` 要**合起来认**，读法同 C 的 `int*`。参数多于一个才用括号：`('a, 'b) Hashtbl.t`。

⚠️ **方向不对称**：函数应用是**前缀**（`f x`），类型构造器是**后缀**（`int list`）。
用户 2026-08-05 深夜叫停过这个方向的深挖，**知道有这回事就够了，别展开为什么**。
