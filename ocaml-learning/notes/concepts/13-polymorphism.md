# 13. 类型变量 `'a`（多态）

> 2026-08-10 讲的，对应 [`../CURRICULUM.md`](../CURRICULUM.md) 的 **B1**。
> **这一篇是 2026-08-11 补写的** —— 当天只把要点记进了 CURRICULUM / MASTERY，没留概念笔记。
>
> **为什么排在阶段 B 的最前面**：后面每个类型签名都带它
> （`List.map : ('a -> 'b) -> 'a list -> 'b list`）。不先给它命名，后面全是天书。

## 13.1 切入点：C# 泛型 `List<T>`

**用 .NET Framework 时代就有的泛型起头**，他熟。
⚠️ **不要用 `record` / 可空引用 / 模式匹配这些新特性当锚**——他自述 C# 停留在旧语法，
新特性对他是额外负担而不是锚点（见 `CLAUDE.md` 第 3 节）。

## 13.2 ⭐ `'a` 是「洞」，不是「基类」

**用户一上来提的猜想（很有内容）：**

> 「如果要我构想泛型的实现，其中一个步骤应该和 C 的预处理一样，要在具体实现的位置进行
> 源码字符串的替换；而 OCaml 的 `'a` 更像是 object 类型，所有其他类型都是从 obj 继承过来的。」

**「不是一回事」这个判断对了**，而且他描述的两条路正好是两种真实策略：

| 策略 | 谁在用 |
|---|---|
| **单态化**（他说的「源码替换」） | C++ 模板、Rust |
| **类型擦除** | Java、**OCaml** |
| **混合** | **C#**：值类型单态化 + 引用类型共享，而且是 **reified**（运行时查得到） |

**要纠正的一点**：OCaml 是**统一表示**，不是**继承**。**`'a` 不是基类，是一个洞。**

### ⭐ 关键讲法（有效，可复用）：区别是「**能不能查**」

| | 能对它做什么 |
|---|---|
| C# 的 `object` | 能 `GetType()`、能强转、能反射 |
| OCaml 的 `'a` | **什么都不能做** |

**演示（一碰就塌）：**

```
let id x = x        →  val id : 'a -> 'a = <fun>      ← 什么都没做，保持 'a
let f x = x + 1     →  val f : int -> int = <fun>     ← 只是加了个 1，'a 立刻塌成 int
```

> **`'a` 不可触碰。你对它做任何事，它就不再是 `'a` 了。**

这正是 ex05 TODO 2 / TODO 6 的考点：`repeat (x : 'a) n` 里的 `x`
**不能加、不能比、不能打印**，只能原样放进表里。

## 13.3 ⭐ 他自己造的第二个类比（表示层对，纪律层相反）

> 「`'a` 更像汇编代码里一个和机器字等长的值，含义取决于它所处的指令和操作数位置。」

**表示层完全正确。** 实测把标记位讲出来他很受用：

```
(Sys.int_size, Sys.word_size)   →   (63, 64)
```

—— 一个字 64 位，`int` 只有 63 位，**差的那一位是 GC 用来区分「立即数」和「指针」的标记位**。
所以 OCaml 的值确实都是「一个机器字」，`'a` 在运行时就是那个字。

**要纠正的一点（纪律相反）：**

> **汇编靠自觉，`'a` 靠证明。**
> **统一表示是「不许看」的结果，不是「随便看」的许可。**

（`Obj.magic` 是那个逃生舱，**故意没展开**。）

## 13.4 同名 = 同类型，不同名 = 无约束

```ocaml
swap : 'a * 'b -> 'b * 'a        (* 'a 和 'b 不同名 → 可以不同，也可以相同 *)
head_or : 'a -> 'a list -> 'a    (* 三个 'a 同名 → 必须是同一个类型 *)
```

**`head_or` 那条为什么必须同名**：如果默认值和元素类型可以不同，
**返回值的类型就说不清了**——空表时返回默认值的类型，非空时返回元素的类型。

ex05 的 TODO 1 第二条测试 `swap (1, 2)` 就是专门验「不同名**也可以**相同」这半句。

## 13.5 ⚠️ 他在这里答错一处，**纠正的重点不是答案**

问：`List.map` 传一个 `int -> int` 合不合法？
他答「`'a` 和 `'b` 必须不是同一个类型」，理由是「OCaml 类型检查很严格」。

**答案错了**（`'a` 和 `'b` 不同名只是「无约束」，不是「必须不同」），
**但真正要纠的是「严格」这个词的含义：**

| | 含义 |
|---|---|
| **健全（sound）** | 不放过会出错的程序 ← **这才是「严格」** |
| **完备（complete）** | 不拒绝正确的程序 |

> **拒绝正确的程序叫「不完备」，不叫「严格」。**

这对概念对他写编译器直接有用，所以当场就给了。

## 13.7 ⛔ 教训：**函数签名里的 `'a`** 和 **类型定义里的 `'a`** 是两件事

**当天我在 B2 踩空，用户第七次喊停：**

> 「这部分有些过于深入了，我感觉可能在系统学习过 type 和构造器后才能开始这方面的练习。」

**诊断**：B1 讲的是**函数签名里的 `'a`**（`List.map : ('a -> 'b) -> …`），
我却直接让他猜 **`type 'a option = None | Some of 'a`** —— 那是**带参数的类型定义**。
他手上的 ADT 经验（ex04 的 `shape`）**全是不带参数的**。

> **等于让他在一个没见过的形状上做推断** —— 正是「给例子前逐个检查概念是否讲过」那条规矩。

**→ 修正已写进 `CURRICULUM.md`：**
「自己定义带参数的类型」挪到 **D1.5**，前置是 D1 的嵌套模式 + 大量 `option` / `list` 的**使用**经验。
**说服他的那句话**：他做了两道列表练习，**从没定义过 `list`**——用和定义是两件事。
