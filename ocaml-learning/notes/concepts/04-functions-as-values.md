## 核心：函数和 int 完全平级

`fun x -> x + 1` 单独求值，顶层回 `- : int -> int = <fun>`——**它本身就是一个值**。

所以 `(fun x -> x + 1) (2 + 3)` 不是什么特殊语法，就是普通的「**函数 参数**」调用，
只不过函数那一格填的是字面量。跟 `(2 + 3) * 4` 里 `(2+3)` 是个算出来的值一样。

**决定性的对照**（这张表是本节的中心）：

| 你想做的事 | int 值 | 函数值 |
|---|---|---|
| 立刻用掉 | `(2 + 3) * 4` | `(fun x -> x + 1) 5` |
| 起个名字留着 | `let n = 2 + 3 in …` | `let f = fun x -> x + 1 in …` |
| 交给别人 | `max (2 + 3) 7` | `twice (fun x -> x + 1) 10` |
| 存进列表 | `[2 + 3; 7]` | `[(fun x -> x+1); (fun x -> x*2)]` |

**一条都不差。** 这就是「函数是一等值」的全部含义。

### `- :` 那个短横线

```
let f x = x + 1     →   val f : int -> int = <fun>
fun x -> x + 1      →   - : int -> int = <fun>
```

**类型完全一样。** 类型里根本不记录「有没有名字」——没有「匿名函数类型」这种东西。
唯一的区别是最前面那格：`val f :` 对 `- :`，**短横线的意思就是「这个值没有名字」**。

### 匿名 ≠ 必须立刻调用

用户一开始的假设是「没名字所以必须当场用掉」。反例：

```ocaml
let twice f x = f (f x) in twice (fun x -> x + 1) 10   (* → 12，交给别人调 *)
[(fun x -> x + 1); (fun x -> x * 2)]                    (* → (int -> int) list，存起来 *)
```

用户自己修正后的说法（**准确，直接引用**）：

> 匿名函数如果不当场使用，就需要一个手段将它以某种形式**锚定**，否则就没有途径使用它。

## 唯一的例外：递归

```ocaml
(fun n -> if n = 0 then 1 else n * fact (n - 1)) 5
Error: Unbound value fact
```

匿名函数**没法引用自己**——body 里想调用自己时连那个词都写不出来。

所以「锚定」有**两重**作用：

1. **对外**：给外界一个把手
2. **对内**：给 body 一个引用自己的把手 ← `let rec` 里那个 `rec` 干的正是这个

第 2 条正是 `03-let-in-scope.md` 第 5 节那个分水岭的另一面：
**普通 `let` 的等号右边看不见自己，`let rec` 看得见。**

> 冷知识（讲过，标注为不用管）：理论上不用名字也能递归（不动点组合子），但实践中一律 `let rec`。

## 多参数函数根本不存在

```ocaml
fun x -> fun y -> x + y     →  int -> int -> int
fun x y -> x + y            →  int -> int -> int
let f x y = x + y           →  int -> int -> int
```

**三种写法编译出来是同一个东西。** 后两种只是第一种的语法糖。

铁证：写成「两个参数」的样子，照样能只喂一个——

```ocaml
let f x y = x + y in f 3    →  int -> int = <fun>
```

如果真是「必须凑齐两个参数的函数」，这里就该报错。

### 三条方向规则

| 规则 | 方向 | 实测 |
|---|---|---|
| `fun` 的箭头（body 贪婪） | **右**结合 | `fun x -> fun y -> x+y` ≡ `fun x -> (fun y -> (x+y))` |
| **类型**里的箭头 | **右**结合 | 标注 `int -> (int -> int)`，OCaml 打回来是 `int -> int -> int` |
| **函数应用** | **左**结合 | `f 3 4` ≡ `(f 3) 4`；`f (3 4)` 报错 |

**一个向右一个向左，正好配合**：

```
定义时向右嵌套：   fun x -> ( fun y -> x + y )
                    └外层吃 x   └内层吃 y
使用时向左剥开：   ( f 3 ) 4
                   └先剥外层    └再剥内层
```

`int -> int -> int` 读作：**「吃一个 int，还你一个『吃 int 还 int 的函数』」**。

### 部分应用带走了什么

```ocaml
let add3  = (fun x -> fun y -> x + y) 3  in add3  5   →  8
let add10 = (fun x -> fun y -> x + y) 10 in add10 5   →  15
```

同一个源表达式，喂不同的第一个参数，产出**行为不同**的两个函数——那个值被**装进函数里带走了**。

所以部分应用不是「得到一个残废的函数」，而是「**把已知信息固化进去的新函数**」。
真实代码里极常见：`List.map (add 3) [1;2;3]` → `[4;5;6]`。

## 优先级全景

| 档次 | 谁 |
|---|---|
| **最高** | **函数应用**（`f 3 + 1` ≡ `(f 3) + 1`，实测 = 7） |
| 中间 | `* / + -` 等中缀运算符 |
| **最低** | `fun ->`、`let … in`、`if`、`match` |

**函数应用和 `fun` 站在两个极端。** 写 `fun x -> f x + 1` 时两条规则同时生效，
结果是 `fun x -> ((f x) + 1)`。

## 求值顺序：两件不同的事，别混

```
f (print "<算1>"; 1) (print "<算2>"; 2)
→  <算2><算1><吃a><吃b>
   └────┬───┘└────┬───┘
    算参数表达式    实际吃参数
    右 → 左        左 → 右
```

- **算参数表达式**：从右往左，**而且这是 unspecified（未规定）的实现行为，永远别依赖**
- **实际吃参数**：一定从左往右（语义要求，`(f 3) 4` 必须先算 `f 3`）

还有两条实测：

- `(print "<函数位>"; fun x -> x) (print "<参数位>"; 7)` → **参数位比函数位还早**
- `let f = fun x -> print "<体>"; x in 42` → **什么都不打印**，函数体在被调用前不执行

> **对写编译器的人**：「求值顺序要不要写进规范」是设计语言时必须做的决策。
> 规定了实现者优化空间小，不规定用户就会踩坑。C 也是 unspecified，OCaml 原样保留了这个坑。

## `let x = e1 in e2` ≡ `(fun x -> e2) e1`

```ocaml
let x = 5 in x + 1      →  6
(fun x -> x + 1) 5      →  6
```

**等价。** 编译器里这叫**脱糖（desugaring）**：前端把 `let` 改写成 lambda 应用，
后面所有阶段就少处理一种语法结构。写 `toylang` 时会真用上。

## 和 C 宏的区别（用户提出的类比，值得记下来）

用户说这像「C 的宏函数 vs C 函数，宏会触发多次副作用」。**洞察对，但对应错了位置。**

C 宏是**文本替换**，参数那段源代码被复制多份，所以参数的副作用跑多遍。
**OCaml 结构上不可能**：

```ocaml
let f x = x + x in f (print "<算参数>"; 3)   →  只打印 1 次
```

`x` 在 body 里出现两次，但参数**先被算成值**再传进去。**宏传的是「表达式」，OCaml 传的是「值」。**

要模拟宏的效果必须显式包成函数（thunk）：

```ocaml
let f t = t () + t () in f (fun () -> print "<算参数>"; 3)   →  打印 2 次
```

| | 传进去的是 | 副作用次数 |
|---|---|---|
| C 宏 | 源代码文本 | 看它在展开式里出现几次，**防不胜防** |
| OCaml 普通参数 | 已算好的值 | **恰好一次** |
| OCaml thunk `fun () -> e` | 待调用的函数 | 调几次就几次，**显式可控** |
