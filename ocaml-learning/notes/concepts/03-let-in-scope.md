# 3. `let … in` 的作用域，以及同名遮蔽

> 2026-08-04 讲的。起因：用户在公开课上看到讲师演示作用域，抄了两个式子回来问，
> 但抄漏了 `in`，正好从语法报错切进这个知识点。
>
> ⚠️ 本文含用户**尚未作答**的那道口算题的答案（最后一节），核对前别让他先看到。

## 一句话

`let 名字 = 值 in <body>` 是**一个不可分割的表达式**，`<body>` 就是这个绑定的作用域，
而且它**贪婪地一路吃到右边的尽头**。

## 1. 只写前半截是语法错误

```ocaml
let x = 5 in (let x = 6)
```

```
Line 1, characters 23-24:
1 | let x = 5 in (let x = 6)
                           ^
Error: Syntax error
```

报错指在**收尾括号**上：解析器读完 `let x = 6` 还在等 `in`，碰到 `)` 就崩了。

> 注意区分：**文件顶层**的 `let x = 6`（不带 `in`）是合法的，那是模块的结构项，不是表达式。
> 这里说的是「`let` 当表达式用」的场合。

## 2. body 贪婪，所以 `in` 后面不需要括号

```ocaml
let x = 5 in x * 2 + 1 - 3     (* → 8，body 是整个 x * 2 + 1 - 3 *)
```

`let … in` 的优先级**比所有中缀运算符都低**——低到几乎不该叫优先级。
准确说法是：body 一直延伸到**当前这层括号（或文件）的结尾**，把右边剩下的全部收走。

能区分两种解析的实测：

| 表达式 | 结果 | 实际解析 |
|---|---|---|
| `2 * let x = 3 in x + 1` | **8** | `2 * (let x = 3 in (x + 1))` ← body 把 `+ 1` 吞了 |
| `2 * (let x = 3 in x) + 1` | **7** | `(2 * 3) + 1` ← 括号把 body 截在 `x` |

**所以括号的作用跟直觉相反**：不是给 `in` 后面「兜住复杂表达式」用的（它不需要），
而是用来**截断**那份贪婪，把整个 `let … in …` 压成一小块子表达式塞进别的式子里。

> 用户一开始正是猜「复杂表达式是不是必须加括号」，方向反了。这是本节最容易错的地方。

## 3. 同名遮蔽：被挡住的是**名字**，不是值

```ocaml
let x = 5 in (let x = 6 in x)          (* → 6  *)
let x = 5 in ((let x = 6 in x) + x)    (* → 11 *)
let x = 5 in   let x = 6 in x  + x     (* → 12 *)
```

第二行 `= 11`：括号里是 6，括号**外面**那个 `x` 仍然是 5。
第三行去掉内层括号就变 12——`+ x` 被里层 body 吞了，那个 `x` 也成了 6。
**那对括号是承重的，不是排版。**

外层的 `x = 5` **从头到尾没有被修改过**，只是在里层那段代码里「叫不出来」。
这和知识点 1（`let` 是绑定不是变量，绑完不能改）是同一件事的两面。

编译器还会白送一条证据：

```
Warning 26 [unused-var]: unused variable x.
        ^ 指向最外层的 x = 5
```

它在说「外层那个 `x` 你压根没用过」——因为里层同名绑定把它挡住了。

## 4. 实战写法：连续绑定不用括号

正因为 body 贪婪，真实代码里这样写：

```ocaml
let a = 1 in
let b = 2 in
let c = 3 in
a + b + c
```

每个 `let … in` 的 body 都是「下面剩下的全部」。读起来像 C 的：

```c
int a = 1;
int b = 2;
int c = 3;
return a + b + c;
```

**区别**：OCaml 这一整坨是**一个表达式**，有值；C 那是四条语句。

## 5. ⚠️ 等号右边看到的是**外层**的绑定

留给用户的口算题（**2026-08-05 已答，答对**）：

```ocaml
let x = 10 in (let x = x + 1 in x) + x     (* → 21 *)
```

拆解：

- 里层 `let x = x + 1`，**等号右边那个 `x` 是外层的 10**，因为新绑定要到 `in` 之后才生效。
  所以里层的 `x` 是 11。
- `(let x = x + 1 in x)` → 11
- 括号外面那个 `x` 不在里层作用域内，还是 10。
- `11 + 10 = 21`

这条是 `let` 和 `let rec` 的分水岭：**普通 `let` 的等号右边看不见自己正在定义的名字**。
