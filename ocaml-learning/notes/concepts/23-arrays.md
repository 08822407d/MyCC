## 23.1 造数组

```ocaml
let a = [| 10; 20; 30 |]               (* 字面量：[| |] 不是 [ ] *)
let b = Array.make 5 0                 (* 长度 5，每格填 0 *)
let c = Array.init 5 (fun i -> i * i)  (* 长度 5，第 i 格填 f i *)
```

```
val a : int array = [|10; 20; 30|]
val b : int array = [|0; 0; 0; 0; 0|]
val c : int array = [|0; 1; 4; 9; 16|]
```

> **数组（array）** — 定长、元素可变、按下标 O(1) 访问的连续存储。类型写作 `int array`。

`[| … |]` 里用**分号**分隔（**逗号还是那个老坑**）。

⚠️ **必须给初值** —— 和 [`22`](22-mutable-record-and-ref.md) 的 22.3 是同一条规则：
OCaml 里没有未初始化。没有 C 那种 `int a[10];` 里面是垃圾的写法。

## 23.2 三个基本操作

```ocaml
let n     = Array.length a     (* 长度 *)
let first = a.(0)              (* 读 —— 圆括号 *)
let ()    = a.(1) <- 99        (* 写 *)
```

**两个要点：**

1. **下标用圆括号 `a.(i)`**，不是 C 的 `a[i]`（方括号在 OCaml 里是列表）
2. **写用 `<-`**，和改可变记录字段是**同一个运算符**

数组元素**天生可变，不需要也不能标 `mutable`**（`mutable` 是记录字段的关键字）。

## 23.3 越界：抛异常，不是 UB

```ocaml
let a = [| 10; 20; 30 |]
a.(5)     (* → 捕获: index out of bounds *)
a.(-1)    (* → 捕获: index out of bounds *)
```

抛 `Invalid_argument "index out of bounds"`，**负数下标一样抛**。

| | C | OCaml |
|---|---|---|
| 越界 | **未定义行为** | **确定地抛异常** |
| 检查时机 | 无 | **每次访问都在运行期检查** |

⚠️ 和 `List.nth_opt` 那条规矩一致：**「用错了」用异常，「正常但没有」用 `option`**
（见 [`14`](14-exceptions.md) 的 14.7）。

## 23.4 🚩 他的总结 + 我补的第三条

**他自己总结出两条**（都对）：

> 「1 是和主流语言一样的下标随机访问，2 是全元素可变」

**漏了第三条，而且那条最容易咬人：**

> **③ 定长。** 数组一旦造出来，**长度就钉死了，不能增删元素。**

### 对照（他熟的两个）

| 语言 | 定长数组 | 可变长的那个 |
|---|---|---|
| C | `int a[10]` | 自己 `realloc` |
| **C#** | **`int[]`** | **`List<T>`** |
| Java | `int[]` | `ArrayList<T>` |
| OCaml | `int array` | `Dynarray`（很新）/ 用列表 |

**每种语言都这么分**，所以「定长」不是缺陷，是分工。

`Array.append` 实测是**造新的**：

```
val a    : int array = [|1; 2; 3|]      ← 原数组一点没动
val b    : int array = [|1; 2; 3; 4|]
val same : bool = false                 ← a == b 为 false，两块不同内存
```

→ **「往数组里追加」是 O(n)**，循环里反复追加就是 O(n²)。

### 要变长怎么办

| 办法 | 什么时候用 |
|---|---|
| **用列表攒**（`::` 是 O(1)），完了 `Array.of_list` | **最常见**（ex07 的套路） |
| `Dynarray`（**OCaml 5.2+**；本机 5.5.0 有） | 真需要会长的数组 |
| `Array.make` 开大的 + 一个 `ref` 记有效长度 | C 的写法，自己管 |

```ocaml
let d = Dynarray.create ()
let () = Dynarray.add_last d 1
let () = Dynarray.add_last d 2
(* Dynarray.length d → 2 ; Dynarray.to_array d → [|1; 2|] *)
```

## 23.5 🔴 他的判断：「像照搬了 C 的数组，连缺陷都一样」—— 要纠正

**他的原话：**

> 「从你描述的所有 ocaml 数组特点来看，似乎它像是照搬了 c 语言的数组，连缺陷都一样
> （如果我没记错的话在 c# 里至少越界会抛异常）」

**两处要说清：**

**① 越界他记反了** —— 上一条我刚给过实测，OCaml **也抛异常**，这一点**和 C# 站一边**。

**② 「定长 + 全可变 + 连续 + O(1)」不是 C 的特色，是「数组」这个结构本身的定义。**

### C 真正独有的缺陷，OCaml 一条都没继承

| C 的毛病 | OCaml |
|---|---|
| 越界是**未定义行为** | **抛异常** |
| **数组退化成指针，长度丢失** | 长度随值走，永远能 `Array.length` |
| 能造出**未初始化**的数组 | `Array.make` 必须给初值 |
| **指针算术**可以走到任意位置 | 没有指针算术 |
| 多维是扁平的，行长必须编译期已知 | `int array array` 是**真嵌套**，行长可以不等 |

**证据 1：长度不会丢**

```c
int f(int a[]) { return sizeof(a) / sizeof(a[0]); }   /* 错的，a 已是指针 */
```
```ocaml
let f (a : int array) = Array.length a
let len_in_fn = f [| 1; 2; 3; 4; 5 |]     (* → 5 *)
```
**数组是一个带头部的值，长度存在它自己身上**，不需要 `func(buf, len)` 那种双参数约定。

**证据 2：多维是真嵌套**

```ocaml
let grid = Array.make_matrix 2 3 0
let () = grid.(1).(2) <- 7
```
```
val grid : int array array = [|[|0; 0; 0|]; [|0; 0; 7|]|]
val row1 : int array = [|0; 0; 7|]        ← 每一行是独立的数组，可以单独传出去
```
行长还可以不等：
```
val jag      : int array array = [|[|1|]; [|1; 2; 3|]|]
val jag_lens : int array = [|1; 3|]
```
C 的 `int grid[2][3]` 是一整块扁平内存，行长必须编译期常量、也不能不等长。

### 老实说 OCaml 哪里确实不如 C#

「要一个会长的数组」更别扭：`Dynarray` 是 **5.2 才进标准库**，非常新；
在那之前的习惯是「先用列表攒，攒完 `Array.of_list`」。C# 的 `List<T>` 从一开始就是默认选择。
（边界检查的运行期开销 C# 也在付，属于同一笔交易。）

### 一句话定位

> **OCaml 的 `array` ≈ C# 的 `int[]`，不是 C 的数组。**
> 长得像 C 是因为「数组」本来就长那样；C 的那些**真缺陷**一条都没继承。

## 23.6 顺带一个对称（接 22.5）

| | 可变性的粒度 |
|---|---|
| **记录** | **逐字段发许可证**（`owner` 钉死、`balance` 可改） |
| **数组** | **全体可变**，没办法只让某几格只读 |

「一堆同类的、都要能改的东西」→ 数组；「一个东西的若干属性，有的能改有的不能」→ 记录。
