# 0. 心智模型澄清：「值 / 求值」到底玄不玄，什么时候能搬 C 经验

> **编号 00，因为它排在所有知识点前面**——但它是 2026-08-07 才写的，
> 起因是用户主动提出的一个元问题：
>
> > 「我一直被『值』『求值』这类概念困扰……我认为这类语言主打一个『不同的思考方式』，
> > 因此大概这都是特别被创造出来的概念和术语，很容易造成混淆和误导。
> > **我不知道到底什么时候可以借用已经掌握的计算机学科知识和通用编程经验来帮助理解。**」
>
> **这是他学 OCaml 以来最重要的一次元反馈。教学时随时可以回指这一篇。**

## 结论（和他的猜测相反）

> **OCaml 没有发明新的「时机」。他的编译原理和编程经验能搬的部分，比他以为的多得多。**

**不要把 OCaml 讲得玄。** 用户是 C / 内核方向的专家，
把语言讲成「另一套现实」既不准确，也直接摧毁他最强的那部分资产。

---

## 一、时机就那几个，和 C 一样

| 阶段 | C | OCaml |
|---|---|---|
| 词法 / 语法分析 | ✅ | ✅ |
| 预处理 | 有（`#define`） | **没有** |
| 类型检查 | ✅ | ✅（更强，且**全部在这一步做完**） |
| 代码生成 | ✅ | ✅（字节码或本地码） |
| 运行 | ✅ | ✅ |
| 运行时类型信息 | 没有 | **也没有**（类型被擦除，不像 C# 的反射） |

**没有第六种时机。**「这是编译期还是运行期」这个问题在 OCaml 里**永远有明确答案**。

## 二、给「值 / 求值」祛魅

> **求值（evaluate）** — 把一个表达式算出结果。**发生在运行时。**
>
> **值（value）** — 已经算完、没法再往下算的东西。

翻译成 C：`3 + 4` 这个表达式**求值**得到**值** `7`。**没有别的意思。**

**唯一的额外含义**：OCaml 里能被求值成值的东西范围更大——
函数、`if`、`match` 在 C 里不是表达式，在 OCaml 里是。
**这是「同一个概念覆盖面更广」，不是「另一套现实」。**

## 三、混乱的三个真实来源（都不玄）

| 来源 | 具体是什么 | 要不要重装直觉 |
|---|---|---|
| ① **`let` 不是赋值** | 它是**新建一个名字**。`let x = 100` 不修改任何东西 | ✅ **必须重装。他的困惑十有八九出在这里** |
| ② **没有「语句」，只有表达式** | C 里 `if` 是语句、`x+1` 是表达式，两类；OCaml 只有一类 | 🔁 **概念变少了**，不是变多 |
| ③ **类型是推出来的** | 不写类型 ≠ 没有类型，是编译器**在编译期**算出来的 | ⚠️ 半搬：静态类型一样，**但没有隐式转换** |

**① 才是真正的分水岭**，而且一点不玄——就是「变量」这个词在两种语言里指的不是一个东西。
2026-08-07 他那道题答 101（实际 4）就是它。

## 四、⭐ 判据表：什么时候能直接搬 C / C# 经验

**这是这一篇的核心产出，讲课时可以直接引用。**

| 主题 | 能搬吗 | 说明 |
|---|---|---|
| 执行顺序、副作用发生的时刻 | ✅ **完全能** | 求值 = 运行时执行，和 C 一致 |
| 内存、指针、别名、生命周期 | ✅ **完全能** | `ref` ≈ 指针，闭包 ≈ 带环境的函数指针 |
| 编译期 / 运行期的分界 | ✅ **能，且 OCaml 更干净** | 没有预处理器、没有运行时类型 |
| 名字解析、作用域 | ✅ **完全能** | 词法作用域，和 C / C# 同一套 |
| 栈、递归、调用约定 | ✅ **完全能** | 尾递归那段就是纯 C 知识 |
| **「赋值」** | ❌ **不能** | `let` 是绑定不是赋值 —— **唯一必须重装的直觉** |
| **「语句」** | ❌ 不能 | 没有语句这个范畴 |
| 类型转换 | ⚠️ 半搬 | 静态类型一样，**但没有隐式转换、没有强制转换语法** |
| 相等 | ⚠️ 半搬 | `=` 结构相等、`==` 物理相等（和 C 反着） |

**左边那五行覆盖了他 80% 的疑问。**

## 五、万能试金石（交给用户的工具）

> **「这件事发生在编译期还是运行期？」**

- 答案是**清楚的时机** → 放心用 CS 经验去理解
- 答案**听起来玄乎、说不清时机** → **是 Claude 没讲清楚，不是他没跟上**，
  他应该当场打断要具体时机

验证过的三个例子：

| 他问过的 | 时机 |
|---|---|
| 「`let rec x = x + 1` 右边的 x 是谁」 | **编译期**（作用域解析），报错也在编译期 |
| 「后面的 `let x = 100` 会不会影响 `f`」 | **编译期**就定死（词法作用域），运行时不再变 |
| 「`f y = x + y` 是不是化简成 `3 + y`」 | **语义上不是**（运行时读环境）；**优化器可能真这么做**（编译期），但那是优化不是语义 |

## 六、「值」和「求值」各自买到了什么（用户追问后补，同日）

用户的原话：

> 「我有必要搞清楚『值』『是一个值』『求值』这些东西在学这个语言中究竟有什么作用，
> **在什么范围内**用它们来思考问题。因为在专门讲函数式编程和 OCaml 的公开课上总是说到它们。」

**答案：两个词各自只买到一样东西，超出那个范围它们就是噪音。**

### 「X 是一个值」= 一份权限清单

> **是值 ⇔ 可以 ①绑给名字 ②当参数传 ③当返回值 ④放进容器**

| | C | OCaml |
|---|---|---|
| `int` | ✅ | ✅ |
| **函数本身** | ❌ **不是值**，只能拿指针；`sizeof(puts)` 非法 | ✅ **是值** |
| `if` / `switch` 的结果 | ❌ 是语句，没有结果 | ✅ 是值 |

**「函数是值」的现金价值**：能写 `let f = fun x -> x+1`、能把函数塞进元组、能返回函数。

### 「求值」= 只回答「什么时候发生」

它唯一有用的场合，是追问**副作用在哪一刻发生**。实测：

```ocaml
let a = (print_string "<绑定时>"; 1)      (* → 立刻打印 *)
let f () = (print_string "<调用时>"; 1)   (* → 不打印，等调用 *)
```

**这就是 thunk 的全部作用**：`fun () -> e` 把求值推迟到调用时。

### 公开课那句「先求所有子式的值」

说的是**求值策略**，结论对用户很友好：

> **OCaml 是按值调用（call by value）——调用前参数先算成值。和 C 完全一样。**

| | 参数什么时候算 |
|---|---|
| C 函数调用 / OCaml | **调用前算完**（按值） |
| **C 的宏** | 不算，原样替换（`MAX(i++, j)` 咬人） |
| Haskell | 用到才算（惰性） |

**讲师强调它，是因为在函数式语言里这不是默认。对 OCaml 记住「和 C 一样」就够。**

### ⭐ 使用范围表

| 在想什么 | 用不用 |
|---|---|
| 能不能传 / 返回 / 进容器 | ✅ 用**「是不是值」** |
| 什么时候打印 / 抛异常 / 递归 | ✅ 用**「什么时候求值」** |
| 参数和函数谁先算 | ✅ 用（答案：参数先，同 C） |
| **这个名字指向谁** | ❌ **别用求值想**，用**作用域**（第五节的两步法） |
| 类型对不对 | ❌ 那是**编译期**的类型检查 |
| 性能 / 栈深度 | ⚠️ 只有尾调用那类相关 |

### ⚠️ 我混过一次，别再混

我先给的判据「能不能写在 `=` 右边」测的是**一等公民（first-class）**，
**不是**「是不是值」。两者不同：

```ocaml
fun x -> x + 1            ← 是值（闭包造好了，没得再算）
print_string              ← 是值（库函数名不是特殊范畴，就是 let 绑好的名字）
[1; 2; 3]                 ← 是值（元素都算完了）
[1 + 1; 2]                ← 不是值，求值后得 [2; 2]
if true then 1 else 2     ← 不是值，是表达式，还要算一步
```

> **值 = 已经算到头的东西；表达式 = 可能还要算的东西。值是表达式的特例（算零步那种）。**

**这个区分对写编译器是核心**：

| 术语 | 编译器里对应 |
|---|---|
| **值** | **范式（normal form）** —— 求值的终点，解释器碰到就停 |
| **求值** | 把表达式逐步归约，直到变成值 |

`eval` 函数的结构就是「是不是已经是值 → 是就返回，否则按规则往下算」。
**「值」在那里是实打实的判断条件，不是修辞。**
