## 已讲知识点

### 1. `let` 是绑定，不是变量声明

- 形式上像 C 的 `int x = 5;`，但有两点不同：
  - **类型不用写**，编译器自己推出来；而且是**编译期就定死**的，不是运行时随便。
    （提醒过：这不同于 C# 的 `var`/C 的 `auto` 那种印象，虽然 `var` 其实也是编译期推导，
    但用户是初学者，重点是让他知道「省略类型 ≠ 动态类型」。）
  - 它是**绑定**不是变量，绑定之后不能改。
- 用到的对比：C 的 `int x = 5;`。
- 状态：已讲，**用户尚未反馈是否理解**。

### 2. 整数和浮点：两套运算符，没有隐式转换（进行中）

- 要点：`+ - * /` 只用于 `int`；浮点是另一套 `+. -. *. /.`；
  两者之间**不会自动转换**，要显式 `float_of_int` / `int_of_float`。
- 用到的对比：C 里 `5 + 1.5` 会把 `5` 悄悄提升成 `double`，OCaml 宁可编译不过。
- 状态：**已出练习 `ex01_int_float`，用户还没写。**

### 3. `let … in` 的作用域，以及同名遮蔽

**详细笔记见 [`concepts/03-let-in-scope.md`](concepts/03-let-in-scope.md)。**
注意这一点是**提前讲的**——原计划排在函数定义之后，因为用户从公开课带问题回来，顺势就讲了。
知识点 2 的练习到现在还没写。

- 起因：用户在公开课上看到讲师演示作用域，抄回来两个式子问是什么意思。
  **他抄漏了 `in`**（`let x = 5 in (let x = 6)`），正好借语法报错切入。
- 讲了三件事：① `let … in <body>` 是不可分割的整体；
  ② body **贪婪吃到右边尽头**，所以 `in` 后面不用括号，括号是用来**截断**它的；
  ③ 同名绑定遮蔽的是**名字**不是值，外层绑定从未被修改。
- 用到的对比：C 的块作用域 `{ int x = 5; … }`；连续 `let … in` 对应 C 的连续声明语句，
  但 OCaml 那一整坨是**一个表达式**。
- 白送的教具：`Warning 26 [unused-var]` 正好指向被遮蔽的外层 `x`，是遮蔽发生的直接证据。
- 状态：**已讲，用户反应良好**（见 MASTERY）。留的口算题 2026-08-05 答对了（21）。

### 4. 函数是值：lambda、应用、部分应用、多参数的真相

**详细笔记见 [`concepts/04-functions-as-values.md`](concepts/04-functions-as-values.md)。**
又是**提前讲的**——用户从公开课带回 `(fun x -> x + 1) (2 + 3)` 问这是什么。

- 核心：`fun x -> …` 本身就是一个值，和 int 完全平级（能对 int 做的事都能对函数做）。
- `let f x y = …` 是 `let f = fun x -> fun y -> …` 的语法糖；**OCaml 里没有多参数函数**，
  `f a b` 就是 `(f a) b`，一次吃一个。
- 三条方向规则：`fun` 箭头右结合、类型箭头右结合、**函数应用左结合**。
- 优先级两极：**函数应用最高**，`fun ->` / `let … in` 最低。
- 求值顺序两件事分开：**算参数右→左（unspecified！）**，**吃参数左→右**。
- `let x = e1 in e2` ≡ `(fun x -> e2) e1` —— 编译器里的脱糖，写 toylang 会用上。
- 用到的对比：C 的宏 vs C 函数（用户提出的，洞察对但对应错位置——
  OCaml 传值不传表达式，副作用恰好一次）。
- 状态：**已讲透，用户掌握良好。**
- ✅ **2026-08-05 补记：「柯里化」这个名字已经给出去了，这一点闭环。**
  切入点是公开课代码里的 `String.concat "\n"` —— 我问「只给第一个参数会得到什么」，
  用户答「**它会变成一个期待输入字符串列表且返回字符串的另一个函数**」，**完全正确**，
  当场贴标签。同时把两个词分清楚了：
  **柯里化 = 语言的设计**（`a -> b -> c` 本来就是一串单参数函数）；
  **部分应用 = 你的用法**（只喂一半就停手）。

### 5. 类型转换：只有显式，转换就是普通函数

**详细笔记见 [`concepts/05-type-conversion.md`](concepts/05-type-conversion.md)。**
这是**知识点 2 的实用补完**，用户问「是不是既没有隐式转换也没有强制转换」。

- `float_of_int` / `int_of_float` 就是普通函数，没有转换语法。类型标注 `(5 : float)` 只检查不改变。
- ⚠️ `int_of_float` 是**朝零截断**不是向下取整，负数上和 `floor` 分道扬镳。
- ⚠️ **「带点 = 浮点版」只是命名习惯不是规则**：比较运算符 `=` `<` 是多态的（`'a -> 'a -> bool`），
  `**` 不带点却只吃 float，`mod` 不带点却只吃 int。
- ⚠️ `==` 是物理相等，`"abc" == "abc"` 是 **false**。C#/Java 背景的经典陷阱。
- 顺带点到了 `ref` / `:=` / `!`（真正的赋值），但只是让他知道存在，**不算讲过**。
- 状态：已讲。**`ex01_int_float` 需要的知识到此全齐。**
