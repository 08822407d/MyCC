#### 答对 / 推理正确的（当天多次）

| 问题 | 他的回答 |

#### ⚠️ 需要订正的两处（都当场纠正了）

1. **「非空那条必须写 `::`」** —— 不对，`| _ ->` 也行。准确说法是
   **「想拿到头和尾就必须写 `::`」**（只有它能造出名字）。
2. **「对 ADT 匹配时所有分支都必须是构造器」** —— 不完全对。
   模式里还能写变量名 / `_` / 常量；**只有"想分辨是哪个构造器"时才非构造器不可**。
   实测 `match c with x -> x` 一个构造器不写也合法，**而且类型退化成 `'a -> 'a`**
   —— 这反过来说明**构造器才是把类型钉死的东西**。

## 2026-08-10 后半 · B1 讲完，B2 我踩空了（第七次喊停）

### B1（`'a` 多态）：讲完了，效果好

他一上来就提了个**有内容的猜想**：

> 「我感觉它们不是一回事。如果要我构想泛型的实现，我觉得其中有一个步骤应该和 C 的预处理一样，
> 要在具体实现的位置进行源码字符串的替换；而 OCaml 的 `'a` 更像是 object 类型，
> 所有其他类型都是从 obj 继承过来的。」

**「不是一回事」这个判断是对的**，而且他描述的两条路正好是两种真实策略：
**单态化**（他说的「源码替换」= C++ 模板 / Rust）和**类型擦除**。
纠正的两点：① C# 是**混合**的（值类型单态化 + 引用类型共享，且 reified）；
② OCaml 是**统一表示**不是**继承**——`'a` 不是基类，是「洞」。

**关键讲法（有效，可复用）**：`'a` 和 `object` 的区别是「**能不能查**」。
`object` 能 `GetType()`；`'a` **什么都不能做**。演示：
`let id x = x` → `'a -> 'a`；`let f x = x + 1` → `int -> int`
——**只要碰一下，`'a` 立刻塌成具体类型**。

**他随后又造了一个好类比**：

> 「`'a` 更像汇编代码里一个和机器字等长的值，含义取决于它所处的指令和操作数位置。」

**表示层完全正确**，用 `Sys.int_size = 63` / `Sys.word_size = 64` 把标记位讲出来，他很受用。
纠正的一点：**汇编靠自觉，`'a` 靠证明**——「统一表示是『不许看』的结果，不是『随便看』的许可」。
（`Obj.magic` 就是那个逃生舱。）**这是他第五次自主给出准确概括。**

**答错一处，值得记**：问他 `List.map` 传 `int -> int` 合不合法，他答「`'a` 和 `'b` 必须不是同一个类型」，
理由是「OCaml 类型检查很严格」。
→ **纠正的重点不是答案，是「严格」的含义**：严格 = 不放过会出错的程序，
**不是** = 到处加限制；拒绝正确的程序叫**不完备**，不叫严格。
顺带给了「健全 / 完备」这对概念，对他写编译器直接有用。

### 他主动问的一个好问题：要不要给每个 try 加兜底

> 「其中几道捕异常的题中没有给出其他异常情况的兜底捕获，我不确定要不要加上。」

**答：不要加，看规格不看习惯。** 4/5/6 的规格是「**特定失败**时给默认值」，
加 `| _ -> d` 会吞掉 `Stack_overflow`、别处抛的 `Not_found` 等**本该炸出来的 bug**。
只有第 7 题的规格是「描述**任何**结果」，兜底才是它的职责。
**三种语言一致**：C# 不该 `catch (Exception)` 吞掉，内核只处理预期错误码、未知的往上返回。
