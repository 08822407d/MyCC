#### ⭐ 两次高质量的自我修正 / 反驳

#### 他主动提出的两个查证型问题（都查了，都有收获）

- 「`Printf` 是不是对 stdio printf 族的封装，行为一样吗？」

  实测差异：`%b`=bool、`%a`=自定义打印函数、`%!`=flush、`%ld`=`int32`，

### 2026-08-06 — ⭐⭐ 指出了我的实验有混淆因素，并设计出能区分的实验

**这是目前为止最高质量的一次推理，级别高于「答对题」。**

背景：我用 `let x = 1 / let f () = x / let x = 2 / f ()` → 1 讲遮蔽。他先答对了机制
（「f 定义时使用的是 x 名称绑定的旧值」），然后**主动指出这个实验证明不了另一件事**：

> 那道例题无法证明函数是运行时才求值的，而不是定义时就"顺便做了某种程度的求值"。
> 可以在名称 x 绑定新值之前、f 定义之后，对 x 绑定的值进行修改，这样应该就能完善地证明。

**逐条判定：**

| 他的主张 | 判定 |
|---|---|
| 原实验对「调用时求值」和「定义时已求值」两种解释都相容 | ✅ **完全正确**，是我讲的时候没意识到的混淆 |
| 设计「定义后、遮蔽前修改 x」来区分 | ✅ 逻辑正确 |

**这是科学方法论**：识别出实验存在混淆变量 → 设计能区分的对照实验。他不是在问「答案是什么」，
是在问「你的证据够不够」。**C/内核背景的人调试系统时就是这么想问题的，迁移过来了。**

补充讲了：还有一条不需要 `ref` 的证法（函数体里放副作用，看打印顺序），
以及「纯 + 不可变 ⇒ 两种求值策略观察不到区别 ⇒ 编译器获得优化自由」——
**这条直接接他的编译器目标**，以后写优化 pass 会反复回到「能不能观察到区别」。
