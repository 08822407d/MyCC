#### ⭐ 两次高质量的自我修正 / 反驳

#### 他主动提出的两个查证型问题（都查了，都有收获）

- 「`Printf` 是不是对 stdio printf 族的封装，行为一样吗？」

  实测差异：`%b`=bool、`%a`=自定义打印函数、`%!`=flush、`%ld`=`int32`，

### 2026-08-06 — ⭐⭐ 指出了我的实验有混淆因素，并设计出能区分的实验

**这是目前为止最高质量的一次推理，级别高于「答对题」。**

背景：我用 `let x = 1 / let f () = x / let x = 2 / f ()` → 1 讲遮蔽。他先答对了机制
（「f 定义时使用的是 x 名称绑定的旧值」），然后**主动指出这个实验证明不了另一件事**：

> 那道例题无法证明函数是运行时才求值的，而不是定义时就"顺便做了某种程度的求值"。
> 可以在名称 x 绑定新值之前、f 定义之后，对 x 绑定的值进行修改，这样应该就能完善地证明。

**逐条判定：**

| 他的主张 | 判定 |
|---|---|
| 原实验对「调用时求值」和「定义时已求值」两种解释都相容 | ✅ **完全正确**，是我讲的时候没意识到的混淆 |
| 设计「定义后、遮蔽前修改 x」来区分 | ✅ 逻辑正确 |
| —— 但对普通 `let` 无法实施 | ⚠️ 他没考虑到「不可变 = 根本没有修改这个操作」；换成 `ref` 后**恰好就是我已经跑过的实验②** |

**这是科学方法论**：识别出实验存在混淆变量 → 设计能区分的对照实验。他不是在问「答案是什么」，
是在问「你的证据够不够」。**C/内核背景的人调试系统时就是这么想问题的，迁移过来了。**

补充讲了：还有一条不需要 `ref` 的证法（函数体里放副作用，看打印顺序），
以及「纯 + 不可变 ⇒ 两种求值策略观察不到区别 ⇒ 编译器获得优化自由」——

### 2026-08-07 — ⭐ ex02_review 综合练习：**六轮迭代做完，四轮是「概念对、位置错」**

**这是第二份真实代码，也是目前信息量最大的一次。** 四道题（`sprintf` / 类型转换 /
`ref` + `;` / `swap`），最后八条自测全过，代码是干净的社区写法。

**但过程比结果有价值** —— 完整的六轮：

| 轮 | 他写的 | 根因 | 性质 |
|---|---|---|---|
| 1 | `Printf.sprintf( "%s" name ^ " = " ^ n)` | 两种造字符串的办法混用 + C 式括号 | 概念混淆 |
| 2 | `/. 2` | float 字面量忘了点 | 低级失误 |
| 3 | `ignore(!r + 1)` | **规则记对了，用反了方向** | ⭐ 见下 |
| 4 | `!a := !b`、`tmp : int ref` | `!` 和「盒子本身」没分清 | 概念混淆 |
| 5 | `let tmp := !a` | `let` 的 `=` 和 `:=` 混了 | 概念混淆 |
| 6 | `let tmp = !a;` | **漏了 `in`** | 知识点 3 的第一课 |

#### ⭐ 第 3 轮那个错最值得记

他写 `ignore(!r + 1); ignore(!r + 1); !r` —— **编译通过，但盒子一次都没被写过**。

他为什么这么写：**记住了「`;` 左边必须是 `unit`」，然后用 `ignore` 去满足它**。
规则完全记对了，只是没意识到 **`r := v` 本身就是 `unit`，根本不需要 `ignore`**。

> **这和 08-06 复习轮第 6 题（把 `sprintf` 当 `printf`，但推理方法完全正确）是同一个模式。**
> **他的错误类型高度一致：好的推理落错对象。** 这类错不是「没学会」，
> 是「学会的东西还没和具体场景挂上钩」。**纠正时应该先肯定推理，再指出对象**，
> 直接说「这里错了」会浪费掉他推理正确这个事实。

#### 什么最有效

**第 4/5/6 轮卡住时，起作用的是「C 指针对照表」**：

| C | OCaml |
|---|---|
| `*p` | `!r` |
| `*p = v` | `r := v` |
| `int tmp = *a;` | `let tmp = !a in` |

给出这张表之后**一次就通了**。理由不是「C 像 OCaml」，
而是**他在 C 里从不犯这个错**——类比的效力来自他对源语言的熟练度。
（这条后来直接影响了类比策略的定稿，见 `CLAUDE.md` 第 3 节。）

#### 风格观察

- **C 式调用括号出现 6 次**（`sprintf(` / `int_of_float(` / `float_of_int(` / `ignore(` ×3）。
  最后靠 **ocamlformat 自动改成 `f (x)`** 收尾 —— 比我反复口头提醒有效得多。
  → **今后这类风格问题，直接跑 `fmt` 让工具说话。**
- 他给出的 `sprintf` 使用判据（「难转换或值很多才用，否则手工拼接」）
  **是从 C 带过来的**，在 OCaml 里前提已经不成立（`^` 便宜、`sprintf` 安全）。
  建议改成「**有没有固定文本模板**」，他接受了。
