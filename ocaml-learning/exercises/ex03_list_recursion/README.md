# ex03_list_recursion — 用递归处理列表

**要编辑的文件只有一个：[`main.ml`](main.ml)**，只改「你的代码」那一段。

## 这题特殊在哪

⚠️ **`match` 的骨架已经替你写好了，你只需要填 `->` 右边那一段。**

这是有意的：你说过模式匹配还只学了一半。所以这一题**不考你发明模式**，
只考「递归怎么写」。等这四题写顺了，再回头补模式匹配会轻松得多。

## 需要的知识（全部讲过）

| 东西 | 在哪讲的 |
|---|---|
| `[]` / `x :: rest`，列表只有这两种形状 | 2026-08-08（今天） |
| `::` 是**造**表，`x :: rest` 是**拆**表，形状相同 | 知识点 9.3 + 今天 |
| `_` 是通配符模式，不绑定名字 | 知识点 9.7 |
| 基准情形 / 递归情形，每次要朝基准靠近 | 知识点 10.4 |
| 尾递归、累加器、内部辅助函数 `go` | 知识点 10.6 / 10.7 |
| `mod` 不带点、只吃 int；判等用一个 `=` | 知识点 5 |

## 四道题

| # | 函数 | 类型 | 练什么 |
|---|---|---|---|
| 1 | `sum_list` | `int list -> int` | 最基本的拆列表 + 递归 |
| 2 | `count_evens` | `int list -> int` | 递归情形里带个判断 |
| 3 | `double_all` | `int list -> **int list**` | **返回一张表**——要用 `::` 造出来 |
| 4 | `sum_tail` | `int list -> int` | 尾递归 + 累加器 + 内部 `go` |

**第 3 题是这组里的转折点**：前两题都是「把表算成一个数」，第 3 题要求你
**一边拆一边造**。造表的工具就是今天学的 `::`。

**第 4 题的考点全在基准情形。** 回想 10.6 里踩过的坑：一路攒在 `acc` 里的东西，
到头了必须交出去；返回 `0` 会让结果恒等于 `0`。

## 关于最后那条一百万的测试

它只是个大输入冒烟测试，**不能证明你写的是尾递归**。
实测过：非尾递归写法喂一千万也不会溢出（OCaml 5 的主栈会自己长），
真要撞出 `Stack overflow` 得上亿级，那样光列表本身就要几个 GB。

所以**第 4 题是不是真的尾递归，由 Claude 读你的代码来判断**。
判据还是 10.6 那条：**递归调用回来之后还有没有活干。**
