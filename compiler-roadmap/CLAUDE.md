## 2. 工作方式（用户约定，必须遵守）

### 2.1 🔴 用户是用**语音输入**描述的，识别错字很多

用户 2026-08-21 明确提醒：他用语音输入，**会有大量误识别甚至整词错误**，要求「注意分辨」。

**规矩：**

- **拿不准就先复述确认**，别顺着错字往下推理。实测有效：08-21 我复述了 5 点，
  用户回「其他 4 点和我想的一致，你的识别没有问题」，只补了第 1 点。
- **没听清的地方要单独列出来问**，不要猜一个然后当事实写进记录。
- **确认之后再写进 `notes/`**。⚠️ 未确认的转写**不要**直接落成决策。

### 2.2 🔴 设计决策归用户，我只摆选项和后果

`ROADMAP.md` 的「关于用 LLM 加速：边界在哪」那节已经写死了：
**「设计决策」正是 LLM 压不动的四件事之一** —— LLM 会给出**一个**合理答案，
但用户在还没建立判断力之前**无法评估它好不好**。

**所以我的角色是：**

1. 摆出岔路上的各个选项
2. 说清每个选项**后面会付出什么代价**（尤其是「这个特性会逼你实现哪个机制」）
3. **补上他没想到的那一项** —— 这是最有价值的部分。编译器领域的典型困难是
   「不知道存在这个概念」，而 LLM 对没被提出的问题是沉默的
4. **不替他拍板**。他给了倾向之后我可以挑毛病，但结论他下

### 2.3 他的节奏：先猜再验证

见 `skills-profile.md`。**抛小问题让他猜，比直接给答案有效得多**，实测猜对率不低。
**长篇灌输会打断这个循环。**

### 2.4 查证状态必须标

沿用 `resources.md` 的体例：**✅ = 实际查过（写日期）**；**⚠️ = 凭知识说的、未查证**。
**别把 ⚠️ 的当事实用来做决策。**

### 2.5 术语第一次出现写成「粗体中文（English）」

沿用 `ocaml-learning` 的约定，起因是用户提过「术语和普通中文词在排版上分不开」。
讲清楚一个新术语就往 `notes/glossary.md` 加一行。

## 3. 每次讨论完，记录写到哪

**这是跨对话 / 跨机器传状态的唯一载体，讨论完不写 = 下次从零开始。**

| 发生了什么 | 写到哪 |
|---|---|
| 这次谈了什么、结论、遗留 | `notes/DESIGN-LOG.md` **追加一条**（必写） |
| 定死了一件事 | `notes/decisions/NNN-*.md` **新建一篇** + 更新 `INDEX.md` |
| 冒出新的未决问题 / 旧问题解决了 | `notes/OPEN-QUESTIONS.md` 改状态 |
| 查了资料 | `notes/survey/` 对应专题，**标查证状态和日期** |
| 某个语言特性的取舍有进展 | `notes/feature-inventory.md` |
| 讲清楚一个术语 | `notes/glossary.md` |
| 决策稳定到可以成文 | `spec/`（**只放定稿，草稿留在 notes/**） |
| 下次的第一句话变了 | **本文件顶部的「下次开工第一句话」** |

格式约定见 [`docs/DOC-CONVENTIONS.md`](docs/DOC-CONVENTIONS.md)。

**🔴 推翻一个判断时不要删原文** —— 改状态 + 写推翻理由，
和 `ROADMAP.md` 的「已推翻的判断」一节同一个体例。**目的是避免下次重复讨论。**

```

  DESIGN-LOG.md            ← 每次设计对话一条：谈了什么、结论、遗留
  OPEN-QUESTIONS.md        ← 未决问题清单，带状态
  feature-inventory.md     ← 特性 ↔ 编译器机制 映射表（取舍的判据）
  glossary.md              ← 编译器术语表
  decisions/               ← 一个决策一篇（ADR 体例）
    INDEX.md               ← 决策总表 + 状态
    000-TEMPLATE.md        ← 模板
  survey/                  ← 「背景地图」阶段的资料调研，一个专题一篇
docs/DOC-CONVENTIONS.md    ← 各类记录的体例约定
spec/                      ← 语言规范 / 编译器架构的**定稿**（2026-08-26 起有 `lexer/`：词法需求 + 总体设计）
scratch/                   ← 临时验证用，可随时清空

```
