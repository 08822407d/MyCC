## 0. 一句话

用 ocamllex 实现**完整 C17 词法分析器**，输入只认 `gcc -E` 产出的 `.i`，
输出与 menhir 兼容的 token 流；主验收标准是
「token 流按原始拼写逐行重打印后，`gcc -fsyntax-only` 零诊断」。

## 1. 范围（决策 005）

### 做

| 项 | 说明 |
|---|---|
| **44 个 C17 关键字** | 32（C89）+ `inline` `restrict` `_Bool` `_Complex` `_Imaginary`（C99）+ `_Alignas` `_Alignof` `_Atomic` `_Generic` `_Noreturn` `_Static_assert` `_Thread_local`（C11）。C17 词法 ≡ C11 ✅ |
| **标点符号** | C17 §6.4.6 全量（发 token 的约 45 种）；含**双字符组（digraph）** `<:` `:>` `<%` `%>` —— 发出与 `[` `]` `{` `}` **相同的 token**（§6.4.6p3「行为等同」，拼写不保留，对 T2 无影响：重打印为规范拼写，gcc 照收）。`#` `##` `%:` `%:%:` **不设 token**（见 §2/§4：合法 `.i` 的行中不可能出现，出现即报错） |
| **标识符** | `[A-Za-z_][A-Za-z0-9_]*`，ASCII only（UCN / 扩展标识符 → 不做清单） |
| **数字字面量** | ✅ 按 **pp-number** 切 + 动作内精确校验（§3，Q13 已确认）；含 `0b`（gcc 默认档放行 ✅ 2026-08-26） |
| **字符 / 字符串字面量** | 前缀：字符串 `u8` `u` `U` `L`，字符 `u` `U` `L`（⚠️ 注意 **C17 没有 `u8''` 字符字面量**，那是 C23 的）。存原始拼写、转义不展开（007）；内容**按字节透明**（字符串内 UTF-8 中文实测通过 ✅ 2026-08-26） |
| **行标记 + `#pragma`** | §4 |

### 明确不做（防滑坡清单 —— 加项必须过一条新决策）

| 项 | 理由 |
|---|---|
| 三元符（trigraph） | gcc 默认自己都不做 ✅；C23 已删。漏出的 `??(` 切成 `? ? (`，parser 自然报错 |
| 注释 / 行接续 | `gcc -E` 已做 ✅；残留视为「未预处理」证据（§2） |
| UCN（`é`）与非 ASCII 标识符 | 真实 `.i` 与 AI 生成代码不出现。字符串**内**的 `\u` 作为普通转义原样保留，不受影响 |
| 转义展开（翻译阶段 5） | 存原始拼写，语义层用到时再解析（007） |
| 相邻字符串拼接（翻译阶段 6） | 推给 parser：`STRING+`（007） |
| C23 词法（`bool` / `nullptr` / 数字分隔符 / `u8''` …） | gcc 11 产不出；普通标识符形状的关键字有兼容风险；将来加行不改结构 |
| GNU 扩展特判 | 词法层为空：`__attribute__` 等全是合法 ISO 标识符 ✅（`0b` 是唯一例外，已收入「做」） |
| GNU 虚数后缀 `1.0i` / `1.0j` | pp-number 会整词吃进、校验时报「非法数字字面量」——方向与 `-std=c17 -pedantic-errors` 一致；AI 生成代码不用 |

## 2. 输入契约（决策 005）

- **只认已预处理输入。** 依据：`gcc -E` 保证注释已删、行接续已拼（✅ 实测），
  且其输出重新切词素与原 token 流一致（⚠️ GCC 文档承诺，未逐字查证；T2 实验旁证）。
- **未预处理探测器**——以下四种情况不报「非法字符」，报人话：
  「**输入似乎未经预处理（第 N 行发现 X），请先执行 gcc -E**」：
  1. 字符串外出现 `/*` 或 `//`（字符串规则先匹配，`"http://x"` 不误报）
  2. 行尾裸 `\`（行接续残留）
  3. 行首 `#` 后跟 `include` / `define` / `if(def)` / `endif` / `undef` 等指令名
     （2026-08-26 复审补：这是最直接的证据）
  4. **行中**（非行首）出现 `#`（gcc -E 输出里 `#` 只出现在行首 ✅ 实测：缩进的
     `#pragma` 也被归到第 0 列）

## 3. 数字词素：pp-number 策略（✅ 2026-08-26 用户确认 = Q13）

**规则**：数字按 C17 §6.4.8 的**预处理数（pp-number）**最长匹配切成单一词素——
`('.'? digit) (digit | 标识符字符 | '.' | [eEpP][+-])*`——
然后在语义动作里用**锚定整词**的精确 C17 数值文法校验并分类为 `INT_LIT` / `FLOAT_LIT`；
整词不匹配 → 报「非法数字字面量」，位置精确到词素。

**为什么不直接按精确文法切**（全部 ✅ 2026-08-26 实测）：

- `gcc -E` 不验证数字：`0x1e+2`、`123abc` 原样进 `.i`
- gcc 编译器把 `0x1e+2` 当**一个** pp-number 报错；精确文法切法会把它拆成
  `0x1e` `+` `2` 三个合法 token **静默放行**——与参照物分歧，而且 **T2 测不出来**
  （往返后 gcc 收到的是被"修好"的流）
- 在全部合法输入上两种切法**等价**（`hello.i` 3122 / `big.i` 23853，token 数逐一致）
- ocamllex 侧一条规则替代五条（hex 浮点 / 十进浮点 / hex / 二进 / 十进整数），
  消除规则间的排序陷阱

**八进制备注**：`0777` 的词素形状就是十进制数字串，八进制**解释**是语义层的事
（与「存原始拼写」一致）；`08` 这类非法八进制也留给语义层报。

## 4. 行标记、位置、`#pragma`（决策 006）

- lexbuf 走 `.i` **物理位置**（ocamllex 默认；不改写 `pos_fname` / `pos_lnum`）
- 行标记规则解析 `# N "文件" 标志*` → **行映射表**追加
  `{物理行; 原文件; 原行号 N; 系统头标志}`
  - 形状全集（`big.i` 509 条 ✅）：`# N "F"` + 0–3 个标志；标志 `1` 进入 / `2` 返回 /
    `3` **系统头**（存表）/ `4` 隐式 `extern "C"`（忽略）
- 诊断打印时二分查表 → 报原始 `.c` 位置；物理位置保留，可直接 `sed -n 'Np' foo.i` 对照
- `#pragma`：单独规则整行吞 + **TODO 注释**（将来 `#pragma pack` 从这里长）
- 其余 `#` 行 → §2 探测器第 3 / 4 条
- **已知实现陷阱**（写给实现那次对话）：
  - **ocamllex 没有行首锚 `^`**：「`#` 必须在行首」要么靠一个 at-line-start 状态位，
    要么依赖 gcc 保证（§2 条 4 就是后者的错误分支）
  - 行标记语义是「**下一行**是原文件第 N 行」，与 `Lexing.new_line` 的调用先后有
    **差一格陷阱**（症状：全部报错整体偏一行）→ T0 有专门用例
  - 行标记可能夹在两个相邻字符串字面量之间——拼接已推给 parser（007），词法层天然无事

## 5. token 与模块结构（决策 007）

- `tokens.mly`：只含 `%token` 声明；`menhir --only-tokens` 生成 `Tokens` 模块；
  将来真语法 `--external-tokens Tokens`；unused 告警 `--unused-tokens` 压
  （三个开关 ✅ 2026-08-26 查证）。可顺手写 **token 别名**（`%token LBRACKET "["`），
  将来文法可读性好（⚠️ 别名语法细节动工时查手册）
- **token 不带位置**（menhir 固定接口 `Lexing.lexbuf -> token`；位置走 `$startpos`）
- 字面量 payload = **原始拼写** `string`（前缀含在内：`u8"..."` 整体是一个 `STRING_LIT`）
- token 种类规模：44 关键字 + ~45 标点 + `IDENT` / `INT_LIT` / `FLOAT_LIT` /
  `CHAR_LIT` / `STRING_LIT` + `EOF` ≈ **95 种**
- 模块划分（**目录落位等 Q12 拍板**）：
  ```
  tokens.mly      # %token 声明（单一事实来源）
  lexer.mll       # 规则本体 + 未预处理探测 + pp-number 校验调用
  line_map.ml     # 行映射表：追加 + 二分查找 + 位置翻译
  token_debug.ml  # to_string / 转储格式（生成的 Tokens 模块不能改，所以另开）
  bin/main.ml     # CLI：读 .i → token 流每行一个打印（即 T1/T2 跑分工具）
  ```
- 错误处理：**首版失败即停**（异常携带映射后的位置 + 人话消息）；
  错误恢复（跳过继续切）记 TODO，不在首版

## 6. 验收（决策 008，⚠️ 暂定 = Q14）

**T0 自造陷阱用例**（必过）：

| 用例 | 期望 |
|---|---|
| `0x1e+2` / `123abc` | 报「非法数字字面量」（✅ pp-number 策略） |
| `0x1p-3` / `.5` / `1e+2` / `0b1010` / `1LL` `0777u` | 合法，原拼写保留 |
| `>>=` | 一个 token（最长匹配） |
| `"a\x41\"b"` | 一个 STRING_LIT，转义原样 |
| 未闭合字符串 / 字符 | 报错，位置对 |
| `dig<:0:>` | 与 `dig[0]` 同一 token 流 |
| 行标记后第一行的报错行号 | 差一格专项（§4） |
| 字符串内 UTF-8 中文 ✅ / 字符串内 `//` | 透明通过 / 不触发探测器 |
| `/*` `//` 裸 `\` 残留 `#define` 行中 `#` | 全部报「未预处理」人话诊断 |

**T1 回归锚点**（✅ 2026-08-26 基线）：`hello.i` 815 行 → **3122** token；
`big.i` 4901 行 → **23853** token；零错误。

**T2 主标准**（✅ 实测可行）：token 流按原始拼写**每 token 一行**重打印 →
`gcc -fsyntax-only` 零诊断（23853 行重编译退出码 0；gcc 报错行号 ≈ token 序号）。
盲区声明：T2 验**切分边界**不验内容解释——内容靠 T0 / T3。

**T3 可选**：`apt install clang` 后 `clang -cc1 -dump-tokens` 逐 token 对拍。
