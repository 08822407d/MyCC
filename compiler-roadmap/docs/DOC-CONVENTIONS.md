# 记录体例约定

> **用途**：这个目录里各类文件怎么写。**改记录之前先看这里**，别自己另起一套。
> 体例基本沿用 `../../ocaml-learning/`，那边已经跑了三周，有效。

## 1. 文件分工（别写串了）

| 文件 | 放什么 | **不放**什么 |
|---|---|---|
| `CLAUDE.md` | 工作说明 + 状态快照 + **下次开工第一句话** | 长篇内容（放 notes/） |
| `README.md` | 给人看的导览 | 给 Claude 的指令 |
| `ROADMAP.md` | 学习路线、排除的方向、已推翻的判断 | 语言本身的设计 |
| `notes/DESIGN-LOG.md` | **每次对话一条**：谈了什么、结论、遗留 | 决策的完整论证（放 decisions/） |
| `notes/decisions/NNN-*.md` | 一个决策一篇：背景、结论、理由、**代价**、备选项、复议条件 | 还没定的东西 |
| `notes/OPEN-QUESTIONS.md` | 未决问题**一行一条** | 问题的详细讨论 |
| `notes/feature-inventory.md` | 特性 ↔ 机制映射表 | 尚未有机制理由的特性名 |
| `notes/survey/` | 资料调研，一个专题一篇 | 结论（结论要落回决策或清单） |
| `notes/glossary.md` | **已经解释清楚的**术语 | 只是提到过的（那有单独一节） |
| `spec/` | 语言规范/架构的**定稿** | 草稿 |
| `scratch/` | 临时验证，可随时清空 | 任何需要保留的东西 |

## 2. 设计日志的一条长什么样

```markdown
## YYYY-MM-DD（机器代号）· 一句话标题

### 谈了什么
### 定下的（表格：问题 | 用户的选择 | 落到哪篇决策）
### 我做的事
### 遗留（→ OPEN-QUESTIONS.md）
```

**必须有的**：日期、机器代号、**结论**、**遗留**。
**新的记在最上面**（倒序）。

**机器代号怎么判断**（⚠️ 别用会话的 `Platform:` 字段，WSL 远程模式下会误判）：

```bash
bash ../ocaml-learning/scripts/ocaml.sh platform
# linux → ubuntu24-pc ｜ wsl / win-gitbash → win10-laptop
```

## 3. 决策记录（ADR）

- 模板：`notes/decisions/000-TEMPLATE.md`，**照抄字段，别省「代价」和「复议条件」**
- 编号**只增不减**，新增一篇**必须**同时往 `INDEX.md` 加一行
- **🔴 推翻不删**：状态改 ❌ + 在原文里写推翻理由，
  体例同 `ROADMAP.md` 的「已推翻的判断」。**目的是避免下次重复讨论**
- **来源必须写清是「用户拍板」还是「我的建议」** —— 后者标 ⚠️ 暂定，
  引用时要说明。混淆这两者是最容易犯的错

## 4. 查证状态（沿用 `resources.md`）

| 记号 | 含义 |
|---|---|
| ✅ | **实际查过**，写日期 + 来源链接 |
| ⚠️ | 凭知识写的、**未查证** |

**别把 ⚠️ 的当事实拿去做决策。** 实测结论要写日期——
`ROADMAP.md` 里「两台机器都没装 LLVM」是 2026-08-05 测的，**过期了要重测**。

## 5. 术语

第一次出现写成「**粗体中文（English）**」，然后往 `notes/glossary.md` 加一行。
**只往「已经解释清楚的」那节加确实展开讲过的**，其余进第二节。

## 6. ⚠️ 用户是语音输入

**转写错字很多。** 拿不准**先复述确认**，别顺着错字推理；
**没确认过的不要写进 `notes/`**，要写就标 ⬜ 待确认。
详见 `CLAUDE.md` 第 2.1 节。

## 7. 回复里的文件链接

沿用 `ocaml-learning/CLAUDE.md` 第 1.6 节的规则：
**给用户的路径要相对当前工作目录**，这样终端里能点开。
