# 背景地图（资料调研）

> **用途**：用户 2026-08-21 选的推进方式是「**先补背景地图，再逐条决策**」——
> 先集中查证整理，**有了地图再开始逐条拍板**。这个目录放调研产出，**一个专题一篇**。
>
> 🔴 **下面这份专题清单是我拟的草案，用户还没确认。**
> 开工前先让他说：**要查哪几个、顺序怎么排、哪些直接砍掉。**（→ `../OPEN-QUESTIONS.md` 的 Q1）
>
> ⚠️ **每篇都要标查证状态**：✅ = 实际查过（写日期和来源）｜⚠️ = 凭知识写的、未查证。
> 沿用 `../../resources.md` 的体例。**别把 ⚠️ 的当事实拿去做决策。**

## 我建议的顺序（也待确认）

**S1 → S3 → S8 → 其余按需。**

- **S1 打头**，因为它给出的是**判据本身**，其他所有专题的结论最后都要落回它那张表
- **S3 紧跟**，因为「砍掉历史包袱」是决策 003 最直接的兑现，
  而且用户是 C 专家，**这一篇他能给出别人给不了的输入**（不是我讲给他听，是他讲给我听）
- **S8 提前**，因为「诊断要做到什么程度」会反过来决定 AST 的结构（**要不要带位置信息**），
  这种结构性的东西**定晚了要返工**
- S2 / S4 / S5 / S6 / S7 / S9 都可以等到 S1 的表初步成形之后按需展开

## 一篇专题的最小内容

1. **要回答的问题**（一句话）
2. **查到了什么**（每条标 ✅/⚠️ + 来源链接 + 日期）
3. **对我们的取舍意味着什么**（**这一节才是产出**，前两节只是原料）
4. **还没搞清楚的** → 回填 `../OPEN-QUESTIONS.md`
