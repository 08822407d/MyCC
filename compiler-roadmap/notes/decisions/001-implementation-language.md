# 001. 实现语言用 OCaml

> **状态**：✅ 已定
> **日期**：2026-08-05 立，**2026-08-21 用户复述确认**（`ubuntu24-pc`）
> **依据来源**：用户自述

## 背景

要挑一门语言来写这个编译器。用户当时的技能分布：C / Linux 内核**专家**，
C# 中等（停在 .NET Framework 时代），C++ 入门偏下，函数式**零基础**。

## 结论

**用 OCaml 写编译器。** 为此从 2026-07-28 起先专门学 OCaml
（进度在 `../../ocaml-learning/notes/PROGRESS.md`，**和本目录是两条线**）。

## 理由

1. **代数数据类型 + 模式匹配是写 AST 和 IR 的最短路径**，
   在 C / C++ 里要用 tagged union 或虚函数体系手工模拟
2. 编译器教学材料里 ML 系是主流：Harvard CS153 就是 OCaml，
   Appel 的书原版是 ML，CMU 15-411 历史上常见 SML/OCaml
3. **概念是跨语言的**：用 OCaml 学会 SSA 和数据流分析之后换到 C++ 是工具问题，
   **反过来不成立**

## 代价 / 放弃了什么

⚠️ **行业岗位普遍要求 C++（外加 Python/CUDA），不是 OCaml**
（2026-08-05 查证，见 `ROADMAP.md` 的「2026 年行业现状」）。
代价是**最后要额外花时间适应 C++ 工程环境**（路线阶段 5）。

**用户接受了这个代价**，理由是概念的可迁移性是单向的。

## 备选项（为什么没选）

| 选项 | 为什么没选 |
|---|---|
| **C** | 他最强的语言，但写 AST/IR 要手工模拟 ADT，学到的很多是「怎么在 C 里模拟」而不是编译原理 |
| **C++** | 目标岗位要求它，但**入门偏下 + 概念和工具双重负担**。放到路线阶段 5，那时是纯工具切换 |
| **Rust** | 没讨论过。⚠️ 如果哪天要重新评估，这里是空白 |
