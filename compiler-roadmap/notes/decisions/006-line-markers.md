# 006. 行标记用行映射表；`#pragma` 先吞；记录系统头标志

> **状态**：✅ 已定
> **日期**：2026-08-26（`ubuntu24-pc`）
> **依据来源**：我的建议，**用户整体确认**（原话「全部按照你建议的执行」）

## 背景

= `OPEN-QUESTIONS.md` 的 **Q5**。`.i` 里活着的 `#` 行有**两类**（✅ 2026-08-26 实测）：

1. 行标记 `# N "文件" 标志*`（`big.i` 里 509 条，仅 4 种形状）；
2. **`#pragma`**（会活过 `-E`；`_Pragma("...")` 也被 gcc 转写成 `#pragma` 行）——
   这是 REQUIREMENTS §4.2 没提到的。`#pragma` 是 C17 §6.10.6 的合法构造，
   是唯一合法活到编译器本体的预处理指令，所以不能「见 `#` 就吞」。

## 结论

- **行映射表（line map）**：lexbuf 维持 `.i` 的**物理位置**（ocamllex 默认行为，
  不改写 `pos_fname` / `pos_lnum`）；行标记规则往表里追加
  `{物理行; 原文件; 原行号; 系统头标志}`；打印诊断时二分查表翻译成原始 `.c` 位置。
  **物理 / 逻辑两种位置都保留**
- **`#pragma`：单独规则整行吞掉 + TODO 注释** —— 将来要支持 `#pragma pack` 等时改动点现成
- **标志 `3`（来自系统头）解析并存入行映射表记录** —— 它是区间属性，不占 token 一个字节；
  将来 parser 报错时能区分「这在系统头里」和「这是你的代码」（`.i` 里 99% 内容来自系统头）

## 理由

1. 调试词法器本身需要物理位置（`sed -n 'Np' big.i` 直接看原文）；
   对外报错需要逻辑位置——只有映射表两个都给
2. 这就是 GCC libcpp line-map / Clang SourceManager 的极简版：
   token 只带紧凑物理位置，映射推迟到打印诊断的时刻
3. OCaml `Lexing.position` 的 `pos_fname` / `pos_lnum` 可直接改写（✅ 查证），
   「就地改写」方案可行，但永久丢物理位置，且有差一格陷阱
   （行标记语义是「**下一行**是第 N 行」，与 `Lexing.new_line` 的先后顺序易错，
   症状是所有报错整体偏一行）

## 代价 / 放弃了什么

- 约 20 行 + 一个查找函数（对比「只跳过」方案的 2 行）
- **列号在宏展开过的行上不可信** —— 行标记只恢复行号。
  这是决策 002 的隐藏代价（已补到那篇），不是本方案能解决的

## 备选项（为什么没选）

| 选项 | 为什么没选 |
|---|---|
| 只跳过（不记任何信息） | 报错只有 `.i` 位置，指进 4901 行的 `big.i`，排查多一跳。但对「AI 生成小文件」场景其实可用，是合格的降级路径 |
| 就地改写 `lex_curr_p` | 永久丢物理位置；差一格 bug 症状隐蔽 |
