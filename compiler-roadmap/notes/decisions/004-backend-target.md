# 004. 后端先输出 LLVM IR 文本

> **状态**：⚠️ **暂定** —— 这是 2026-08-05 我在路线讨论里给的建议，
> **用户从来没有正面确认过**。引用它的时候要说明是暂定的。
> **日期**：2026-08-05
> **依据来源**：**我的建议**（部分查证）

## 背景

编译器后端要吐出什么：直接吐目标机器的汇编，还是吐 LLVM IR 交给 LLVM 收尾。

## 结论（暂定）

**阶段 1 的后端打印 LLVM IR 文本（`.ll`），然后 `clang foo.ll -o foo`。**

配套的两条技巧：

1. **不要碰 LLVM 的 OCaml binding** —— 接口就是一个文本文件，
   绕开整个 C++ API 和 opam 装 llvm 包的版本地狱
2. **不要自己构造 SSA** —— 局部变量一律 `alloca` + `load`/`store`，
   一个 phi 节点都不写，交给 LLVM 的 `mem2reg` 自动提升（`clang -O1` 即可）。
   ⚠️ 这是 LLVM 官方教程的标准做法（**2026-08-05 凭知识写下，未逐条查证**），
   估计能砍掉约 30% 的难度

## 代价 / 放弃了什么

- **拿不到指令选择、寄存器分配、栈帧布局的一手经验** ——
  这些正是用户 x86-64 汇编熟练度能派上用场的地方
- 路线上靠**阶段 2（Harvard CS153）**补回来：那门课就是 `LLVM IR → x86-64`

## 白捡的好处（装了 LLVM 之后）

```bash
llvm-as foo.ll -o /dev/null      # 语法 + 类型检查
opt -passes=verify foo.ll -S     # 结构验证
```

报错精确到行，**相当于免费送的编译器输出测试工具**。

## 🔴 硬前提没满足

**LLVM 工具链两台机器都没装**（2026-08-05 实测：gcc 15.2.0 有，clang / llc / opt / llvm-as 全没有）。
`sudo apt install clang llvm`。⚠️ **距实测已过去两周多，动手前重新确认一次。**
