# 008. 词法验收标准：四级阶梯 T0–T3，T2（gcc 往返）为主标准

> **状态**：✅ 已定
> **日期**：2026-08-26（`ubuntu24-pc`；同日先以 ⚠️ 暂定提出，**用户当日确认**「都按照你推荐的方案走」，Q14 关闭）
> **依据来源**：我的建议，用户确认

## 背景

L7：成功标准是什么。用户是 OCaml 初学者——没有客观验收，
「我写对了没有」就只能依赖他此刻最缺的那种判断力。

## 结论

| 级 | 标准 | 定位 |
|---|---|---|
| **T0** | 自造陷阱用例全过（清单见 `../../spec/lexer/DESIGN.md` §6） | 必须；指哪打哪 |
| **T1** | 真实 `.i` 零错误切完。基线（✅ 2026-08-26 实测）：`hello.i` 815 行 → **3122** token；`big.i` 4901 行 → **23853** token | 必须；回归锚点 |
| **T2** | **往返测试**：token 流按原始拼写**每 token 一行**重打印 → `gcc -fsyntax-only` 零诊断（✅ 实测可行：23853 行重编译退出码 0） | **必须；主标准** |
| **T3** | `clang -cc1 -dump-tokens` 逐 token 对拍 | 可选（clang 未装，apt 有；pycparser 2.22 已装但吃不了真实 `.i`，做不了 oracle） |

## 理由

1. **T2 的裁判是 gcc，不是自己写的代码**——完全不依赖用户对 OCaml 的判断力
2. T2 抓的正是词法器最易错的一类 bug：切分边界（最长匹配、字符串边界、转义吞字）
3. 每 token 一行使 gcc 报错行号 ≈ token 序号（2026-08-26 Fable 5 复审的改进，原方案是空格连接单行）

## 代价 / 放弃了什么

**T2 有盲区，诚实声明**：它主要验**切分边界**，不太验**内容解释**——
原始拼写原样回吐自然对得上。内容层正确性靠 T0（指定用例）和 T3（外部 oracle）。

## 备选项（为什么没选）

| 选项 | 为什么没选 |
|---|---|
| 只用自造用例 | 全部测例出自同一个头脑，无外部校验 |
| 只用 T1「零错误切完」 | 太弱：切成一堆错误 token 也算「零错误」 |
